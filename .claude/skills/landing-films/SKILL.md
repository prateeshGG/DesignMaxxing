# Landing films

A film here is a **deterministic web page**: `window.seek(t)` places every element for second `t`. A headless browser captures each frame at device scale 2, and ffmpeg encodes the frames. Everything is made in code with this repo's engine. Nothing is generated by a video model or assembled in a scene or template tool.

**The quality bar is `landing/films/how-it-works.html`** (19.5 s, 1920×1200, voice and music). The founder approved it. Start from it, not from scratch. The four older films (`compare`, `devices`, `motion`, `closing`) are first drafts below the bar and need the same treatment before use.

## Workflow

1. **Study the reference film.** Pull a frame every 1.5–2.5 s into a contact sheet. Write the grammar as rules: shot length, the one thing that moves, transitions, camera, type, art layer, texture. Take the grammar, never the content, logos or artwork (`references/grammar.md`).
2. **Capture sharp sources** (`references/capture.md`).
   - Never upscale; capture again at device scale 2 (desktop) or 3 (phones).
   - Use both passes: animated, and reduced-motion with transitions frozen. Choose per section.
   - Crop on DOM-measured bounds, never by eye.
   - Take regions under one shared animated background in **one** shot.
   - Keep the frame whose counters have settled.
   - Run the blank-crop check on every crop.
   - Check robots.txt and credit every site.
3. **Write copy that matches the pictures.**
   - The opening line says what the viewer gets ("Search real websites, section by section."), not an abstract slogan.
   - A search query must describe what *every* result really shows: a studio site has no dashboard; a gradient-art hero has no product visual.
   - Never describe how a library or product is collected or built behind the scenes.
4. **Storyboard before rendering.** Make a beat grid (time → what happens → transition → sound) and 6–10 stills rendered from the real timeline. Get the founder's comments before the full render.
5. **Build the film** (`references/motion.md`).
   - Rooms side by side on a wide world plane, with a camera that moves between them.
   - Camera moves: push-ins on details, expo pull-backs, one whip pan with motion blur, match cuts.
   - Springs with one overshoot, masked text reveals, light sweeps.
   - One focal action at a time; holds of 0.5–1 s.
6. **Annotate with callouts.**
   - Each label sits in **empty space**, never on content.
   - **One straight arrow** runs from the label to the target, with an arrowhead.
   - Add a pen mark only where it helps: an underline for a wide line of text, a small ring for a button, nothing on large art.
   - Animation order: label → arrow → mark, about 1 s in all.
   - The camera holds until the callout is fully drawn.
7. **Render and check.** Render at device scale 2, then encode 1920×1200 H.264 (CRF 22) and VP9 (CRF 33). Pull frames **from the encoded file** and go through the QA list below.
8. **Sound** (`references/audio.md`).
   - Voice: an energetic, **dry** voice from the Fish Audio connector, with a delivery tag per line.
   - Music: a **licensed** track, credited, timed so a downbeat lands on the main cut.
   - Mix: voice about 10 dB above the music, −16 LUFS.
   - No code-synthesised sound effects.
9. **Ship.**
   - One MP4 + WebM that **contain the audio track**.
   - In the page: `muted autoplay loop playsinline`, playing only while visible.
   - A clearly visible sound button that shows the **current state** ("Sound off" with a crossed speaker, "Sound on" with waves) and restarts from 0 when turned on.
   - Verify in a headless browser that after the click `muted` is false and `webkitAudioDecodedByteCount` grows.
   - Commit sources and the shipped files, not `out/` renders.

## QA checklist (every item must hold)

- [ ] Fonts are the real ones (local files; a blocked font host fails silently).
- [ ] Every screenshot is sharp at the largest camera zoom used; nothing upscaled.
- [ ] No source defect is visible:
  - no counter caught mid-roll;
  - no section cut through the middle;
  - no seam in shared animated art;
  - no blank or poster-only crop where a video should show.
- [ ] Copy matches the visuals (opening line, search query, labels).
- [ ] Callouts: labels in empty space, straight arrows, no oversized rings, fully drawn before the camera moves.
- [ ] Blur only on fast moves; holds are crisp; the camera never shows past the edge of the world.
- [ ] Loops are seamless where the film loops.
- [ ] Sound has no synthesised effects; the voice is dry and clear above the music; the music credit is on the page.
- [ ] The sound button shows the current state and actually unmutes (tested).
- [ ] File size is about 10 MB or less for 20 s at 1920×1200.

## Hard rules

- Motion is made only with this repo's film engine. No AI video models, no template or scene tools, no stock motion packs.
- No solid black buttons or bars in films or pages: soft surfaces with soft tinted shadows.
- Credit the sites shown on screen or in the caption; never present third-party logos as customers.
- Music must have a licence that allows commercial use, and its required credit must be shown. Never scrape sites that sit behind bot checks.
- Never pick a voice that imitates a real person or a real channel's announcer.
- Secrets (TTS keys and similar) live in environment variables only, never in the repository or a page.

## What the founder rejected (do not repeat)

| Rejected | Do this instead |
|---|---|
| Soft, low-resolution films built from upscaled screenshots | Re-capture at device scale 2/3 |
| Fallback system fonts | Local font files |
| Curvy connector lines, a big circle around large art, labels over content | Straight arrows, small marks, labels in empty space |
| The same kind of video everywhere on a page | Vary the motion per section |
| Code-synthesised whooshes, pops and pad ("fush fush") | Licensed music only |
| A roomy, flat voice | An energetic, dry ad voice |
| A silent default file with the sound version only in a second file | One file with audio |
| A sound button that shows the action instead of the state | Show the current state |
| Motion from third-party scene tools | Motion only from this engine |
