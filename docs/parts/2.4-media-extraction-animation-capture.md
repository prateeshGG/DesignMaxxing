## 1. Purpose & Scope

**Purpose.** 2.4 answers one question for every captured page: *what media and motion does this page contain, and what evidence of it do we keep?* It runs **inside the capture child** (2.2) as the `media` module, during the `extract` step, within `LIMIT_MEDIA_EXTRACT_S` (20 s, doc 22 §5). It finds media through five layers (DOM, CSS, network, runtime, visual; doc 08 §13), builds a **media inventory** (one `MediaManifest` per attempt), stores the original bytes of what policy and the 25 MB cap allow as raw `ASSET` artifacts, detects animation, takes a live still for items that have no file, and prepares the three representations of animated media: `original`, `poster`, `normalized_video` (§14, D-13). Producing the **derived** representations (poster, normalized video, normalized SVG, SVG preview) is specified as an idempotent function whose *placement* (inside the attempt or in an offline step) is an open question (OQ-2.4-2). 2.4 never decides what is publishable (2.10), never builds graph rows (3.2), never classifies (4.x), and never makes anything public (F-18).

**Phase:** `[V0]`. The only V1 element is the scroll-pass recording; 2.4 keeps a forward-compatible hook (F-13, F-40, §3.9, OQ-2.4-28). Interaction-triggered motion (hover, menus, modals, tabs, accordions) is V1 in 2.7 (F-02), not here.

### 3.3 The five discovery layers

Order of processing is the order below (doc 08 §13). Every layer reads the page only; none clicks, scrolls, navigates or starts media (R3).

| # | Layer (`asset.discovery_layer`) | What it looks at | Mechanism | Finds that others miss | Cost note |
|---|---|---|---|---|---|
| 1 | **`dom`** | `img`, `picture`, `source`, `video`, inline `svg`, `canvas`, `iframe`, `object`, `embed`; open shadow roots; same-origin iframes (A5) | One in-page walk in batches; reads element facts (`currentSrc`, `srcset`, `poster`, `autoplay`, `loop`, `muted`, `controls`, `duration`, `readyState`, `paused`, `complete`, `naturalWidth`), geometry, visibility and an element-path signature | Elements with no network request of their own (inline SVG, canvas), broken images, hidden items, `loading=lazy` images not yet loaded | Cheap; bounded by `LIMIT_DOM_MAX_NODES` (2.2) |
| 2 | **`css`** | Computed `background-image`, `mask-image`, `content` (including `::before` and `::after`), `image-set()` forms | Computed-style read on elements with a rendered box, in batches | Backgrounds, masks, sprite sheets, CSS-injected images | The most expensive read; stops at the budget and returns `partial` |
| 3 | **`network`** | `NetworkLog` entries (2.2): resource types `image` and `media`; `fetch/xhr/other` entries only when the URL or runtime layer points to a Lottie or SVG file | Join by final URL with layers 1–2; entries nobody referenced become network-only items | Assets loaded by script (Lottie JSON, canvas textures, image sequences, preloaded media), redirected URLs, the real MIME type and size | Free (already in memory); body access is OQ-2.4-5 |
| 4 | **`runtime`** | Motion and player libraries (Lottie, GSAP, Framer Motion/Motion, Anime.js, Barba, Locomotive Scroll, Lenis, Three.js, Rive), `document.getAnimations()`, the computed `animation-name` scan, SMIL elements, optional init-time observe-only data (OQ-2.4-6) | Page-world reads of globals, custom elements and DOM markers; animation objects; no page behaviour is changed | Motion without a file (CSS, WAAPI, JS libraries), Lottie instances, canvas context type | In S1 limited by the freeze (OQ-2.4-19) |
| 5 | **`visual`** | Regions that visibly change but that layers 1–4 cannot explain | Only if 2.2 reports motion (`animations_running` or `StabilityProbe`) with no cause found; clipped pixel samples ~1 s apart compared in memory; no computer vision in V0 (OQ-2.4-29) | Motion the page hides from the other layers (closed shadow roots, cross-origin frames, custom engines) | Last, smallest budget; the first thing dropped when time runs out |

"If something is visible but unidentifiable → screen recording / computer vision. This minimizes unnecessary processing" (doc 08 §13): layer 5 is a fallback by design.

### 3.4 Media kinds → representation

**Poster policy** (R22). `animation_artifact` is append-only with unique `(animation_id, role)` (1.2), so a poster cannot be replaced later. The rule is therefore fixed per kind: items whose file FFmpeg can decode (video, GIF, APNG, animated WebP/AVIF) get a derived frame as `poster`; every other animated item gets its live still. A live still is also kept as raw evidence for items that have both, only if the budget allowed it, but it is not linked.

### 3.5 Animation detection signals and what they fill

This is the V0 "animation detection" of the hierarchy. A row in `animation` exists only when there is evidence of motion (R16); each carries `evidence[]` in the manifest.

| Signal | Layer | Evidence read | `animation.type` | `trigger` | `duration_ms` | Notes |
|---|---|---|---|---|---|---|
| CSS animation | runtime | `document.getAnimations()` CSS animations; computed `animation-name`, `-duration`, `-iteration-count`, `-timeline` scan | `css_animation` | `load` (default), `scroll` if `animation-timeline` is scroll/view | duration × iterations; NULL if infinite (iterations kept in manifest) | Finished load animations survive in the computed-style scan (`animation-name` stays); `getAnimations()` only shows live ones [Assumption A11] |
| CSS transition | runtime | Computed `transition-duration` and `-property` above zero on elements with a rendered box; grouped by element signature, capped | `css_transition` | `hover` only when a readable stylesheet rule with `:hover`/`:focus` sets a transitioned property for the same element; else NULL | The declared duration | Declared, not triggered: nothing is hovered in V0 (F-02) |
| Web Animations API | runtime | Non-CSS `Animation` objects from `getAnimations()` | `js_library` (`library: waapi` in manifest) | `load` if running at observation | From timing, else NULL | |
| SVG SMIL | dom, network | `animate`, `animateTransform`, `animateMotion`, `set` elements in inline SVG or in fetched SVG text | `animated_svg` | `load` | From `dur`, else NULL | `<img>` and CSS SVGs are scanned as text from the fetched body |

### 3.8 State of one extraction (not stored)

```
PREFLIGHT ─► DOM ─► CSS ─► NETWORK ─► RUNTIME ─► ACQUIRE ─► STILLS ─► VISUAL ─► MANIFEST ─► (ModuleResult)
   │          └─ each stage can end ok / partial / skipped / failed / timeout; a failed stage never stops the later ones,
   │             except that MANIFEST always runs, also on abort (R24, R25)
   └─ media_allowed = false  ⇒ mode = inventory_only: ACQUIRE, STILLS and own fetches are skipped (R4)
```

Derive step, per derivation (not stored; the registry row is the memory): `PLANNED ─► CACHE_HIT (done)` or `PLANNED ─► RUNNING ─► DONE | FAILED | SKIPPED`.

## 4. API Surface

**No HTTP endpoints, no new events in V0, no `/internal/*`** (F-24). 2.4 exposes (a) the in-child module contract, (b) a reader, (c) the derive function and its queue consumer, (d) configuration keys, (e) CLI commands. One new consumer queue and one new event are **proposed** in OQ-2.4-2 and OQ-2.4-13.

### 4.1 In-child module contract

```ts
// slot defined by 2.2 §4.4 (ModuleResult and AttemptContext are 2.2's)
extractMedia(ctx: AttemptContext): Promise<ModuleResult>   // ModuleResult.status ∈ ok | partial | failed | timeout | skipped
```

| Aspect | Contract |
|---|---|
| When called | Step `extract`, after 2.3's `capturePage`, in the motion state (2.2 R12, step 5), strategies S0 and S1. S2: `skipped` by 2.2. S3: not called |
| Inputs used from 2.2 | `ctx.page`, `ctx.signal`, `ctx.budget`, `ctx.networkLog`, `ctx.passes`, `ctx.stability`, `ctx.strategy`, `ctx.heartbeat`, `ctx.output`, `ctx.input.ids`, `ctx.input.limits` |
| **Inputs 2.4 needs and 2.2 does not yet provide (P)** | `ctx.input.policy.media_allowed` and the asset size cap (OQ-2.4-1); a way to read response bodies from `NetworkLog` (OQ-2.4-5); an observe-only init-time probe slot and its data (OQ-2.4-6); a read-only view of section bounds written by 2.3 (OQ-2.4-7); a clipped-screenshot primitive (OQ-2.4-8); a read of the current pass state (OQ-2.4-19) |
| Heartbeat substeps | `ctx.heartbeat('extract', 'media.dom' \| 'media.css' \| 'media.network' \| 'media.runtime' \| 'media.acquire' \| 'media.stills' \| 'media.visual')` at each stage and after every acquired item. Substeps are for logs only (2.2 §4.2); `progress` rises per item |

## 5. Business Rules & Edge Cases

### 5.1 Rules

Rules without a decision ID in "Basis" are this spec's design inside 2.4's own scope (P); each depends on a named open question or assumption.

| # | Rule | Basis |
|---|---|---|
| R1 | **Slot and phase.** 2.4 runs only in the `media` slot, step `extract`, in S0 and S1. S2 skips it and S3 never calls it (the unit then has no inventory; 2.10 knows from `module_results.media`) | DC-05, doc 22 §7; 2.2 §4.5 |
| R2 | **Motion state.** Animation and media state are read in the motion state, after `exitStatic()` (2.2 R12). In S1 the freeze and reduced-motion emulation apply from context creation, so computed animation facts and the media the page chose to load can differ from S0 (a page may swap a video for its poster under reduced motion, [Field observation] §5.7). The manifest records `environment` and sets `motion_detection_limited`; the inventory of an S1 unit is not comparable with an S0 inventory | DC-20, 2.2 OQ-2.2-14; OQ-2.4-19 |
| R3 | **Read-only toward the page.** No navigation, click, form, scroll, `play()`, `pause()`, seek, hover, or script that changes behaviour. Evaluations only read. Stills use clipped capture by page coordinates, never scroll-into-view. Autoplay state is recorded as found | F-16, F-02, 2.2 R7, R15 |
| R4 | **Policy gate.** `media_allowed` (and any other denial of `evaluateCollection(source_id, 'media')`, which the supervisor evaluates at attempt start) is read once. If false: `mode = inventory_only`: the manifest and `animation` records are produced, but no bytes are acquired, no own fetch is made and no still is taken (OQ-1.5-18's suggestion, extended in OQ-2.4-1). The reason is recorded in `environment`. The capture itself is not affected: crawl denial is checked at lease (1.4), not here | D-44, 1.5 R-2, OQ-1.5-18 |
| R5 | **25 MB cap.** An item is stored only if its bytes are ≤ 25 MB. Checked first by `Content-Length` or `Content-Range` total, then by the bytes received (a lying header is not trusted, A10). Over the cap: not stored, listed in `skipped[]` as `too_large`, inventory row and `animation` row kept. 1.3's `ArtifactTooLarge` is the second line | F-10, 1.3 R10, E14 |
| R6 | **No streams.** HLS/M3U8 is never downloaded: the manifest URL goes in `source_url`, the item is `delivery = stream`, and only a live still and metadata are kept. DASH (`.mpd`) and MSE (`blob:` video sources) are treated the same by analogy to F-13 (OQ-2.4-18) | F-13 |
| R7 | **DRM.** If `mediaKeys` is set or an `encrypted` event was seen, the item is `drm: true`, `delivery = stream`, nothing is downloaded and nothing is attempted | MB§60, doc 08 edge table |
| R8 | **Only what the page asked for.** Bytes come from responses the page itself triggered. Own fetches are allowed only for the exact `currentSrc`/`src` of a rendered `video`/`source` or another rendered element whose response body cannot be read from the log. Never fetched: `srcset` alternatives, backgrounds of unrendered elements that were never requested, linked files (`<a href>`), anything found by following links, anything off the page. No crawling | F-46, F-10 |
| R9 | **Own-fetch rules.** Every URL and every redirect hop passes the SSRF guard (private, loopback, link-local, metadata ranges) → `skipped[]` `ssrf_blocked`. Same honest user-agent and context settings as the attempt; no extra headers, no credentials added. One at a time, spaced as OQ-2.4-5 settles (no more than F-10's 1 request/s and 2 concurrent per domain under any reading). A 401, 403, 429 or 5xx is recorded and **never retried or worked around** (hotlink protection included). Timeout and abort bounded by the remaining budget | F-10, F-20, DC-01, DC-08, SC-03 |
| R10 | **Privacy of bodies.** Only recognized media is ever stored. A JSON/XHR/fetch body inspected as a possible Lottie is dropped immediately if it is not one: not stored, not logged. Request bodies, cookies and authorization values are never read or recorded. Logs carry host and path hash, never query strings | F-19 spirit, F-15, 2.2 R19 |
| R11 | **Type decision order.** Bytes sniff (magic bytes, header chunks) beats `Content-Type`, which beats extension and element tag. A mismatch is recorded (`mime_header` vs `mime_sniffed`) and the stored `mime_type` is the sniffed type. A CDN that labels a Lottie `text/plain` is still a Lottie | §13 network layer |
| R12 | **Inventory granularity and cap.** One item per (resource identity, section); further occurrences of the same resource in the same section raise `occurrence_count` (OQ-1.2-13's natural key). Order: DOM order, then network-only items by first request time. At `LIMIT_MEDIA_MAX_ITEMS` the rest is dropped by priority (rendered before unrendered, larger area first) and `items_truncated` is set. Infinite lazy galleries stop here | DC-01, doc 22 #5, OQ-1.2-13 |
| R13 | **Discovery layer value.** `asset.discovery_layer` is the first layer, in processing order (dom, css, network, runtime, visual), that found the item. All layers that found it go in `layers_found` | OQ-1.2-14, §13 [Assumption A6] |
| R14 | **Visibility is recorded, not filtered.** Hidden, offscreen and zero-size items are inventoried with `visibility` flags (carousel slides, mobile-only images, `display: none` variants). Their bytes are stored only if the page already loaded them and OQ-2.4-16's rule allows | DC-16, doc 08 |
| R15 | **Section association.** Each item gets the section with the largest intersection of the item's `bounds` with the section's bounds (2.3, CSS px, page coordinates); ties go to the lower `order_index`. An item that crosses sections also lists `spans_order_indexes` (a shared animated background behind nav, hero and logo row is one item, [Field observation] §5.7). Items with `position: fixed` or `sticky`, or measured when `scroll_y_at_measure ≠ 0`, get `order_index: null` and the flag in `visibility`. Network-only items have no section. If 2.3 gave no bounds (S2, failure), every `order_index` is null and 3.2 may associate by `bounds` later | DC-21, doc 08, OQ-2.4-7 |
| R16 | **Animation rows need evidence.** A row exists only with at least one `evidence` entry (§3.5). Static items never get one. `trigger` is set only when provable (CSS timeline, scroll-library signature, readable `:hover` rule, autoplay state); otherwise NULL, which 1.2 allows. A library being present without visible motion is `library_only` | IF§13, WF§3 |
| R17 | **One row per motion source.** A video's motion is one `animation` row tied to its asset; its container's CSS is not duplicated. CSS transitions are grouped by element signature and capped at `LIMIT_MEDIA_MAX_ANIMATIONS` | DC-01 |
| R18 | **Visual layer is a fallback.** It runs only if 2.2 reports running animations or a changing `StabilityProbe` and layers 1–4 left them unexplained; it compares clipped pixel samples in memory and stores at most one still per region. No computer vision in V0 | §13, OQ-2.4-29 |
| R19 | **Live stills.** Taken only for items that have no file FFmpeg can decode (§3.4 poster policy) and for visual-layer regions; clipped by page coordinates; `frame_selection = 'arbitrary'` and `frame_at_ms` recorded for animated content; one still per item; skipped when `mode = inventory_only`, when the region exceeds the screenshot limit (OQ-2.2-25) or when the budget is spent. A still shows what the page rendered, including any overlay on top (gate check 8 sees that) | DC-20, §14 |
| R20 | **Raw immutability.** Original bytes are stored exactly as the browser delivered them (decoded content encoding; `content_encoding_removed` recorded). | R21 | **Derived is regenerable and never upscales.** Derived artifacts reference the root raw artifact, are keyed by `(kind, producer, producer_version, input_hash)`, never replace a raw, and a derived image is never wider than its source (DC-20, 1.3 §4.3). | R23 | **Internal only.** Nothing 2.4 stores is public: video, SVG, Lottie JSON, stills, posters and normalized videos are internal evidence (F-18, 1.2 R15, 1.3 R17). A future display derivative is 6.1's decision with counsel | F-18, F-42 |
| R24 | **Budget discipline.** All stages share `min(LIMIT_MEDIA_EXTRACT_S, remaining attempt budget)`. Stages 1–4 run first (cheap and needed for the gate). No new sub-operation starts after the soft limit (2.2 OQ-2.2-5's 85% rule). No synchronous operation longer than about 1 s [Estimate]; the module yields between items so 2.2's heartbeats keep flowing (DC-03). The manifest is assembled from in-memory state and can be written in under a second at any moment, also after `abort` | DC-01, DC-03, doc 22 §5 |
| R25 | **Failure containment.** A stage error is caught, recorded and the stage skipped; later stages still run. `failed` only if the DOM stage could not run at all. Media never fails the attempt | DC-10, 2.2 A12 |
| R26 | **Determinism.** Same page state gives the same ordering and the same `media_item_id` values; no wall-clock times are recorded except `frame_at_ms` relative to the stage start | DC-02, DC-12 |
| R27 | **Facts, not judgements.** 2.4 reports counts, bounds, load states and flags. It never scores, labels roles (hero, background, demo, advertisement) or decides publishability | DC-06, 2.2 R17 |
| R28 | **No evasion.** No hotlink workarounds, no forged or altered signed URLs, no DRM handling, no login, no proxy or fingerprint tricks | DC-08, SC-03, MB§60 |
| R29 | **No new top-level requests.** Own fetches are subresource-style requests to media URLs, not navigations. They count in `network_summary.requests_total` through the shared log | F-10, 2.2 OQ-2.2-1 |
| R30 | **Same-site and cross-origin frames.** Same-origin iframes are traversed within the node cap; cross-origin and closed shadow content is not entered (the network layer still sees what they load, as network-only items) | doc 08, A5 |

| R32 | **Idempotent and cache-first derive.** `deriveMedia` checks the registry cache before any work and never produces a second row for the same key | 1.3 R8, §43 |

### Reliability

- A media failure never fails an attempt (R25, DC-10); the worst outcome is an empty or partial inventory with a status.
- The module holds no state beyond the attempt (R26) and writes only under `/batch` (2.2 R2).
- The derive step is cache-first and idempotent (R32); a crash leaves at most an orphan blob that 1.3's GC removes.
- Runtime changes to 2.4 (and to Chromium) need the torture suite and canary (DC-12).

### Security and privacy

- Page media is untrusted input. Byte sniffers in the child are bounded, never `eval`, parse JSON only after size and prefix checks, and run inside the container sandbox (F-20).
- **SVG and Lottie are active content.** Originals are stored untouched and never served from our origin (F-18, 1.3 R17). Rendering or sanitising happens only in the derive step, in an isolated, no-network page with page scripts off (a Lottie is rendered by our own pinned player from data, not from the page), and FFmpeg runs with timeouts, output caps and no network protocols (OQ-2.4-14).
- Every own fetch passes the SSRF guard (R9, F-20).
- Images can contain faces or personal text. In V0 only public marketing pages are collected and assets stay internal (F-19, F-18); pixel-level redaction is V2.
- Signed or tokenised media URLs are evidence but must not leak into logs or search (R10, OQ-2.4-22).
- Competitor-library hosts (F-41): OQ-2.4-24.

### Cost recording

The child records no `CostEvent` (2.2 §7); browser time is 2.9's. The derive step's FFmpeg, Sharp and renderer time is a cost of its own: OQ-2.4-27 (owner 1.6). Derived outputs are cached by input hash (§43).

### Observability (data for 1.8)

Per attempt (from the manifest, so no extra instrumentation): items by `asset_type` and layer; stage statuses and `elapsed_ms`; bytes stored; `skipped[]` reasons; `images.broken`, `images.pending_lazy`; `motion_detection_limited`; `scroll_pass_eligible`. Per derive run: derivations by `kind` and status, tool time, cache-hit rate. Useful derived metrics: layer yield (items found **only** by layer N, to show whether a layer earns its cost), share of videos over 25 MB, share of streams, S1-versus-S0 inventory difference, `media` partial rate. Every log line carries `run_id, job_id, unit_id, attempt, strategy, step` plus `substep` (1.4 `logContext`, 2.2 §4.2).

## 8. Open Questions & Assumptions

### Open questions

Each entry: question — why it matters — **suggested default (a suggestion, not a decision).**

- **OPEN QUESTION OQ-2.4-1:** 2.2's `AttemptInput` has no `policy.media_allowed`, no asset size cap and no media limits, and nothing says who calls `evaluateCollection(source_id, 'media')`. Also what `media_allowed = false` means exactly, and what other denials of purpose `media` mean (1.5 R-2 applies its rules 8–10, about breakers, snoozes and robots, to `media` too). — The child has no database access (2.2 R2), so the supervisor must pass the decision in; without it 2.4 cannot respect D-44. — **Suggested default:** owner 2.2 adds `policy.media_allowed` (boolean) and `limits.asset_max_bytes` and the `LIMIT_MEDIA_*` values to `AttemptInput`; `buildAttemptInput` calls `evaluateCollection(source_id, 'media')` at attempt start and passes `allowed`; owner 1.5 confirms that false means "inventory only" (OQ-1.5-18: no binaries, no own fetches, no stills; inventory and `animation` rows kept) and that any other denial of purpose `media` also gives inventory-only for that attempt without affecting capture (crawl denial is a lease-time matter, 1.4).
- **OPEN QUESTION OQ-2.4-2:** Where and when are the derived representations (poster, normalized video, normalized SVG, SVG preview) produced? Inside the 90 s attempt (2.2 §3.4 lists raw types only, and the child has no FFmpeg budget), in an offline step after the unit is accepted, or later on demand? Which units get derived? — The attempt is already over-subscribed (OQ-2.2-5); FFmpeg on a 25 MB video can take longer than the whole `extract` cap; derived data is regenerable (§6), so rejected units need none. — **Suggested default:** in-attempt work is limited to originals, live stills and the manifest; derivation is an offline step (`deriveMedia`, §4.4) run from a new consumer queue `ev.media` on `capture_unit.finalized`, acting only on `ACCEPTED` units, on the crawler machine at low priority; added to 1.4 §4.5 by the review. Decide with 1.4, 2.9, 3.2.
- **OPEN QUESTION OQ-2.4-3:** How much of the normalized-video path is V0? The hierarchy puts all three representations in V0, but the first consumers are internal only (review and classification; the viewer is 6.6 [V1] and F-18 keeps video, SVG and Lottie internal), and rendering a Lottie or animated SVG to video needs an isolated browser renderer and a Lottie player, which no source chooses. — Cost and storage versus usefulness; "normalized video" for Lottie and animated SVG is the most complex path. **Founder to confirm.** — **Suggested default:** V0 builds the FFmpeg path first (video, GIF, APNG, animated WebP/AVIF → `poster` and `normalized_video`) and the SVG path (`normalized_svg`, `svg_preview`); Lottie and animated SVG keep `original` + live-still `poster` in V0, and their `normalized_video` is built (isolated page, our own pinned player, no network) when the spike shows such items are common or 6.6 needs them. Either way the contract in §4.4 does not change.
- **OPEN QUESTION OQ-2.4-4:** Does V0 record a short clip of canvas/WebGL, or only a still? F-13 lists "Canvas/WebGL: record rendered output" inside its V1 bullet, doc 08 §14 says "recorded as rendered result" without a phase, and the hierarchy puts canvas handling in V0. A clip needs a recording technique (context video, which is a context option owned by 2.2, or frame sampling by clipped screenshots) and real time inside a 20 s budget. — Decides whether `normalized_video` exists for canvas in V0 and whether 2.2 must enable recording at context creation. — **Suggested default:** V0 = detection, inventory, one live still and a pixel-difference check (`motion_confirmed`); clip recording is V1 together with the scroll pass; raw `VIDEO` is reserved for it (OQ-1.3-5).
- **OPEN QUESTION OQ-2.4-5:** How does 2.4 get bytes, and how are own fetches paced? 2.2's `NetworkLog` is "requests, responses, failures, sizes" with no body access; Playwright can read a response body only while the browser still holds it; `<video>` files load as ranges, so the browser rarely holds a whole file; and an own fetch is a further request to the site or its CDN under F-10's 1 request/s and 2 concurrent (2.2 OQ-2.2-1 leaves the counting open). — Owner 2.2 for `NetworkLog`. — **Suggested default:** `NetworkLog` entries expose `resource_type`, `status`, `content_type`, `content_length`, and a lazy `body(maxBytes)` that reads the browser's copy; only when that is unavailable (and only for rendered items, R8) does 2.4 make an own fetch through the context, one at a time, at most `LIMIT_MEDIA_MAX_OWN_FETCHES` per attempt, at least 1 s apart per host, never retried. If OQ-2.2-1 settles on "subresources are not paced" this stays the conservative reading.
- **OPEN QUESTION OQ-2.4-6:** May 2.4 install observe-only probes at context creation (through 2.2's `addInitScript`) to record `requestAnimationFrame` call rates, canvas `getContext` types, and `Element.animate` calls? 2.2 R10 forbids patching identity (plugins, languages, WebGL vendor, `navigator.webdriver`); wrapping page APIs to count calls is not identity spoofing but it does touch the page environment and is detectable. — Without it, canvas context type is unknown and JS-driven motion is seen only by pixel difference. — **Suggested default:** allowed if 2.2 and the founder agree it is not evasion: wrappers call the original, return its result unchanged and record counts only; 2.2 owns the install point and exposes the data through `ctx` (as it does for its own probes); if refused, 2.4 records `context: 'unknown'` and relies on the visual layer.
- **OPEN QUESTION OQ-2.4-7:** How does 2.4 read section bounds? 2.2's `AttemptContext` has no field for them, and they are produced by 2.3 in the `capture` step. — R15 and DC-21 need them. — **Suggested default:** after `capturePage`, 2.3 publishes a read-only list `{order_index, bounds_x, bounds_y, bounds_w, bounds_h}` (1.2's `section` fields, CSS px, page coordinates) and 2.2 exposes it as `ctx.sections`; 2.3 leaves the page at scroll top (A2); if the list is empty 2.4 sets every `order_index` to null and 3.2 can associate later from `bounds`. Owners 2.3 and 2.2.
- **OPEN QUESTION OQ-2.4-8:** Which code takes the live stills, and may it avoid scrolling? 2.2 R15 allows scrolling only inside 2.3, and 2.3 owns screenshots; Playwright's element screenshot scrolls the element into view. — A still must not alter page state (R3) and must respect Chromium's size limit (OQ-2.2-25). — **Suggested default:** 2.3 exposes a clip-by-page-coordinates screenshot primitive (full-page-style clip, no scroll) that 2.4 calls; 2.4 supplies the region and never calls `locator.screenshot`. Owners 2.3, 2.2.
- **OPEN QUESTION OQ-2.4-9:** What is the manifest's raw type and how is it found? 1.3's list has no "inventory" type; OQ-1.3-5 suggests `LOG` for manifests and 2.2's OQ-2.2-23 uses `LOG` with `meta.role` for capture context. — 3.2, 2.10 and 6.4 must locate it without guessing. — **Suggested default:** raw `LOG`, `mime_type` `application/json` (gzip per OQ-1.3-9), `meta.role = 'media_manifest'`; found through `readMediaManifest` (§4.2), which filters by `meta.role` on the unit's `result_attempt_id`.
- **OPEN QUESTION OQ-2.4-10:** Natural keys. 1.2's suggested key for `asset` is `(screen_id, coalesce(hash, source_url), section_id)`, which is NULL-ish for canvas, embeds and streams with no URL, and `animation` has no defined key. 2.4 supplies `media_item_id` (deterministic per page state). Also where `occurrence_count` lives. — R5 (idempotent normalization) and DC-02. — **Suggested default:** 1.2 adds `asset.item_key text NOT NULL` with unique `(screen_id, item_key)` and `animation.item_key` with unique `(screen_id, item_key)`, both filled from the manifest (`media_item_id`, `animation_key`); `media_item_id` = hash of (resource identity, section order index or `none`, structural element path for items without a URL), exact formula an implementation detail with the properties in §3.7; `occurrence_count` stays in the manifest. Owner 1.2, consumer 3.2.
- **OPEN QUESTION OQ-2.4-11:** Value sets are missing cases (extends OQ-1.2-14): iframe embeds (`asset.type` has no `embed`), Rive and other binaries (`other`), and motion nobody explains (`animation.type` has no `unknown_motion`); `trigger` allows NULL. Also canvas 2D uses `webgl_animation` because D-13 names no other type. — The CHECK constraints are 2.4's to fill (1.2 §3.3 "Value owned by 2.4"). — **Suggested default:** add `asset.type` values `embed`, `other` and `animation.type` value `unknown_motion`; keep `webgl_animation` for 2D canvas with the context type in the manifest; durations in milliseconds as OQ-1.2-14 says.
- **OPEN QUESTION OQ-2.4-12:** Homes for metadata with no column: frame count, transparency, compression estimate, library names, `has_animation` and `animation_types` flags (doc 08), visibility, `occurrence_count`. `raw_artifact.meta` is immutable after registration (1.3), and R14 of 1.2 restricts JSONB. — Feature List H lists frame count, transparency and compression; search filters (5.1) may want `has_animation`. — **Suggested default:** cheap file facts known inside the attempt (header-derived frame count, fps, duration, alpha flag for PNG/WebP/GIF) go into `raw_artifact.meta`; deeper decode-based facts are produced by the derive step as a JSON derived artifact of kind `media_probe` (added additively by 2.4, 1.3 OQ-1.3-7); everything else stays in the manifest; 1.2 adds columns or a screen-level flag only when 5.1 or 6.x needs a filter.
- **OPEN QUESTION OQ-2.4-13:** The derived step finishes after 3.2 has already created graph rows, and `animation_artifact` is append-only with no 1.2 function to add a link afterwards. — Posters and normalized videos would never be linked. — **Suggested default:** 2.4 emits `capture_unit.media_derived` (§4.4) after its transaction; 3.2 consumes it and appends `animation_artifact` rows idempotently (matching `animation.item_key`); 1.2 adds the append function. Alternative: 3.2 waits for derivation (changes 1.4's routing, not preferred). Owners 1.2, 3.2, 1.4.
- **OPEN QUESTION OQ-2.4-14:** Process, placement and sandbox of the derive step. It runs FFmpeg, Sharp, an SVG sanitizer and possibly a headless renderer on hostile files, so it needs the container sandbox (F-20), timeouts and output caps, and CPU that on the founder's computer competes with capture (F-45). Is it a `worker-crawler` job, an `ml` script, or a `worker-app` job? — Security boundary and machine load. — **Suggested default:** a job with placement `crawler`, run in a sandboxed container from the same image with no network, a read-only input and one scratch volume, FFmpeg with `-protocol_whitelist file` and output caps, one worker at low priority, paused while capture slots are busy or the machine is under load (2.9's host-load rules). Owners 1.1, 1.7, 2.9.
- **OPEN QUESTION OQ-2.4-15:** Normalization parameters: video container and codec, maximum dimensions, frame rate, maximum duration, audio, poster frame, WebP quality, SVG preview size. Doc 08 gives only the three-representation names (`.mp4`, `-poster.webp`) and "video is canonical, GIF only a preview". — Cost, quality and a future viewer's needs. — **Suggested default:** MP4 (H.264), no audio, never larger than the source (DC-20), dimensions and duration capped at values chosen in the spike; poster = first frame whose pixel variance is above a floor, searched in the first quarter of the duration, saved as WebP; SVG preview PNG at the SVG's own size.
- **OPEN QUESTION OQ-2.4-16:** What is stored versus inventory-only? Tracking pixels, 1×1 images, `display: none` and not-yet-loaded items, tiny icons: the Feature List says "automatically collect", F-10 caps size but not count. — Storage and noise. — **Suggested default:** inventory everything; store bytes only for items the page already loaded and that are rendered, or loaded and at least a minimum rendered area (value chosen in the spike); never store unrendered, unloaded items; tracking pixels are inventoried, not stored.
- **OPEN QUESTION OQ-2.4-17:** Per-attempt media limits (DC-01): items, downloads, total media bytes, own fetches, animation rows, stills, sniff bytes. Nothing is decided. — "Everything is bounded", and 2.2's `LIMIT_ATTEMPT_MAX_BYTES` is itself open (OQ-2.2-20). — **Suggested default** (placeholders for the spike): 300 items; 60 downloads; 60 MB media per attempt (under 2.2's suggested 250 MB attempt total); 6 own fetches; 50 animation rows; 12 stills; 64 KB sniff window (JSON key check) with full parse only for size-capped Lottie candidates.
- **OPEN QUESTION OQ-2.4-18:** Streaming and `blob:` beyond HLS. F-13 names HLS/M3U8 only. DASH (`.mpd`) and MSE (`blob:` `currentSrc`) are the common cases on large sites and cannot be downloaded as a file anyway; `blob:` images and SVGs can be read by a page-world fetch. — Copyright and cost reasoning of F-13 applies equally. — **Suggested default:** DASH and MSE are treated as streams (poster and metadata only); `blob:` images and SVGs are read once through the page and stored; `blob:` video is a stream.
- **OPEN QUESTION OQ-2.4-19:** Effects of S1's freeze and reduced-motion emulation, and of an incomplete `exitStatic()` in S0 (OQ-2.2-14: reversibility is unverified), on media and animation facts. Reduced motion can change which media the page loads; a freeze can hide animation values. — 2.10 should not treat a smaller S1 inventory as a defect, and 3.2/3.4 should not compare S0 with S1 inventories. — **Suggested default:** 2.2 exposes `passes.state()` (motion/static) and a freeze flag; 2.4 records them in `environment`, sets `motion_detection_limited` in S1, and reads declared values where possible; 2.10 and 3.4 read `environment` before comparing. Owners 2.2, 2.10, 3.4.
- **OPEN QUESTION OQ-2.4-20:** What the gate takes from 2.4. Gate check 6 needs broken and pending image ratios, DC-21 needs media bounds, doc 06 lists "media completeness" among score inputs; thresholds and weights are 2.10's (doc 22 §15 #2 "not decided"). Also what 2.10 expects of S2/S3 units that have no inventory. — So facts exist in the right shape before 2.10 is written. — **Suggested default:** 2.10 reads `summary.images`, `summary.videos`, item `bounds`/`visibility`/`load_state` and `environment`, through `readMediaManifest`; a missing manifest in S2/S3 means "not measured", not "zero media".
- **OPEN QUESTION OQ-2.4-21:** Which media facts feed change detection (DC-15, 3.4). Rotating carousels, ads and A/B tests change media without a real redesign; F-14's state hash has no media term. — False "changed" rates. — **Suggested default:** 3.4 hashes the set of (resource identity, section) of non-volatile items; 2.4 sets `hints.volatile` for iframes and for items in auto-advancing carousels; media never creates a new state (F-14).
- **OPEN QUESTION OQ-2.4-22:** Asset URLs carry secrets (signed query strings). `asset.source_url` is a provenance field (`asset_source`) but also text near search; F-19 screens extracted text, not URLs. — Leaking a signed URL into the index or UI. — **Suggested default:** the manifest and raw evidence keep the full URL; `asset.source_url` stores the URL with query values removed when they match secret/signed patterns (3.3's list); logs carry host and path hash only; 3.3 confirms.
- **OPEN QUESTION OQ-2.4-23:** Retention and sizing of media. F-33 lifecycle covers raw HTML/DOM/traces and recordings only; third-party `ASSET` blobs, stills and derived media have no rule, and 1.3 §7.1 does not include media bytes. — Cost and the takedown surface. — **Suggested default:** treat `ASSET` like other raw evidence (kept, no tiering in V0), derived media regenerable and deletable first; 1.3 revises its estimate after the 20-site spike with real media bytes per unit.
- **OPEN QUESTION OQ-2.4-24:** Does the competitor deny-list (F-41) apply to asset hosts? 1.5 matches source domains. A page might embed media hosted by a denied library. — F-41 says never collect from them. — **Suggested default:** yes: 1.5 exports a pure host matcher (like 2.2's robots matcher); 2.4 skips binaries from denied hosts (`skipped[] host_denied`) and keeps the inventory row.
- **OPEN QUESTION OQ-2.4-25:** Media the lists mention but no spec covers. (a) Font files appear in doc 08's network layer (`woff2`) but fonts belong to 4.8 [V1]; (b) `og:image`/favicons are metadata URLs seen in the DOM by 2.3; (c) audio and PDFs are on no list; (d) sprites and image sequences (Feature List H) have no handling beyond hints. — Boundaries and gaps. — **Suggested default:** (a) not stored by 2.4: 2.2's `NETWORK_METADATA` already records the requests, 4.8 reads them; (b) not fetched; 2.3's DOM capture keeps the URLs; (c) not collected; (d) stored as ordinary images with `hints.sprite_like` / `hints.sequence_like`; no sprite slicing or sequence assembly in V0.
- **OPEN QUESTION OQ-2.4-26:** Sharing the `extract` step. 2.2 §4.4 puts 2.3's DOM/accessibility/style/performance snapshot and 2.4 in the same step, whose cap is 20 s in doc 22 §5 and 2.2's suggested enum caps (OQ-2.2-6), while the child total may be about 60 s (OQ-2.2-5). — Whether media gets its full 20 s. — **Suggested default:** 2.3's snapshot runs first with its own small allowance; 2.4 gets the rest, never more than `LIMIT_MEDIA_EXTRACT_S`; the numbers come from the spike. Owners 2.2, 2.9 with 2.3.
- **OPEN QUESTION OQ-2.4-27:** Who records the cost of derive work (FFmpeg, Sharp, renderer time) and how? — Every expensive step is cost-recorded (principles, §43), `CostEvent` details are 1.6's, and no wave-1 spec defines a CPU-time cost. — **Suggested default:** the derive job records one `CostEvent` per run with unit id, seconds of tool time and bytes; owner 1.6 defines the shape.
- **OPEN QUESTION OQ-2.4-28:** Scroll-pass hook (V1). Eligibility per unit or per site, where the video is linked, and its budget. — F-13 says "one scroll-pass video for hero + sections, only on sites where an animation library/video/canvas is detected" and no V0 work is allowed (F-40). — **Suggested default:** per unit, computed in V0 as `summary.scroll_pass_eligible` and `summary.motion_libraries`; the V1 spec (a later 2.4 spec) decides recording, the `screen_artifact` role and the budget.
- **OPEN QUESTION OQ-2.4-29:** Scope of the visual layer in V0 and its worth. Doc 08 says "screen recording / computer vision" as a last resort; computer-vision models are Not decided (doc 06) and recording is OQ-2.4-4. — A layer that costs time but rarely finds anything. — **Suggested default:** V0 = pixel-difference only on unexplained regions; the 20-site spike reports how many items only this layer found; if almost none, it is switched off by config until needed.

### Assumptions

- **[Assumption] A1:** Inventory rows are per page-occurrence collapsed within a section (consistent with OQ-1.2-13's natural key); both profiles of a page are separate units with separate manifests.
- **[Assumption] A2:** When `extract` starts, 2.3 has left the page at scroll top (doc 08's settle sequence ends at the top); the manifest records `scroll_y_at_measure` so a wrong assumption is visible.
- **[Assumption] A3:** The motion pass state is restored well enough by `exitStatic()` for animation facts to be read (OQ-2.2-14 asks to verify).
- **[Assumption] A4:** A clipped screenshot of a playing, non-DRM `<video>` or canvas in headless Chromium shows the current frame; the spike verifies it. Software GL makes WebGL canvases render (OQ-2.2-13).
- **[Assumption] A5:** Open shadow roots and same-origin iframes can be walked within `LIMIT_DOM_MAX_NODES`; closed roots and cross-origin frames cannot.
- **[Assumption] A6:** A single-valued `discovery_layer` ("first layer that found it") is enough for provenance (`asset_source`); `layers_found` in the manifest keeps the rest.
- **[Assumption] A7:** Reading computed styles on every rendered element is affordable inside the budget; it is bounded and stops as `partial` otherwise (to be measured).
- **[Assumption] A8:** Parsing untrusted media headers in TypeScript inside the sandboxed child, bounded by size, is acceptable; deep decoding never happens in the child.
- **[Assumption] A9:** The honest user-agent and the attempt's context are enough for media fetches; no per-site header is needed (no evasion, DC-08).
- **[Assumption] A10:** `Content-Length` and `Content-Type` headers can be wrong; bytes decide (R5, R11).
- **[Assumption] A11:** `document.getAnimations()` shows only running or in-effect animations, so finished load animations are found by the computed-style scan.
- **[Assumption] A12:** `animation.bounds` of a CSS animation is the bounds of its target element at measurement.
- **[Assumption] A13:** `<audio>` and `<track>` elements are out of scope (on no list).
- **[Assumption] A14:** A manifest exists only for attempts that ran the `media` module; the unit's manifest is the one of its `result_attempt_id`.
- **[Assumption] A15:** Hash-skip and re-crawl decisions happen before units are created (2.2 A8; 3.4), so unchanged pages are not re-extracted and their media is not fetched again.
- **[Assumption] A16:** `asset-service` (listed in doc 02) is not used in V0; `media-service` holds all of 2.4.
- **[Assumption] A17:** Storing third-party assets internally as raw evidence is covered by F-18's "stay internal evidence" and the per-source `media_allowed` switch; counsel confirms with the display question (E5, 8.2).
