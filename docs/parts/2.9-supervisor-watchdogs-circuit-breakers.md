## 1. Purpose & Scope

**Purpose.** 1.4 defines what a lease, a heartbeat and a unit state *are*. 2.9 is the code that *acts* on them. It is the one small, long-lived, browser-free process on the crawler machine that takes units from the scheduler, runs each one in a disposable, memory-limited capture child, watches the child from outside, kills it when it misbehaves, and writes the result (or the failure) back through 1.4. Around that loop it runs the watchdogs that stop one bad site, one bad URL, a full disk or a dead dependency from stalling collection. The capture code is never trusted to time itself out (DC-03). Nothing in collection waits without a bound (DC-01).

**Phase:** `[V0]`. Later-phase hooks are marked **[hook]**.

## 3. Data Model

**2.9 owns one new table** (`global_breaker`, (P), OQ-2.9-21) and the *behaviour* behind rows other Parts own. It writes `capture_session` (schema: 1.4), the breaker columns of `source` (schema: 1.5, only through `recordBreakerTransition`) and `intake_hold` rows (only through 1.4's `holdIntake`/`releaseIntake`). Everything else it touches is read-only. Table and enum naming follows 1.2 (snake_case singular). **Every lease, deadline, breaker and age comparison that is persisted uses the Postgres clock** (OQ-1.1-21); in-process timers use a monotonic clock [Assumption].

### 3.3 `capture_session` usage

A session = one capture child process run inside one `capture_job` (F-21, DC-07). Rules: one session has at most one live child; `units_served` counts units started in the session; `lease_owner` is the supervisor instance id.

**`lease_owner` format (P, 1.4 delegates it to 2.9):** `supervisor:<host>:<instance_uuid>` where `<host>` is the crawler machine host name and `<instance_uuid>` is a UUIDv7 generated at each process start. A restarted supervisor is therefore a different owner than before.

**`end_reason` values (P, text, additive; 1.4 delegates them to 2.9):**

| `end_reason` | Meaning |
|---|---|
| `recycled_units` | 50 units served (DC-07) |
| `recycled_age` | 30 min since spawn (DC-07) |
| `job_drained` | no more eligible units in this job (after the linger in OQ-2.9-6) |
| `idle` | linger expired with no unit |
| `deadline_kill`, `step_deadline_kill` | attempt deadline or a step budget hit; child killed |
| `heartbeat_lost` | child silent for 60 s; killed |
| `memory_kill` | RSS limit or runtime OOM kill |
| `crash` | child exited without a result |
| `lease_lost` | `heartbeat` or `withLease` threw `LeaseLost` (expired or revoked) |
| `protocol_error` | invalid or unexpected child message |
| `db_unreachable` | self-fence: no successful `heartbeat` for 60 s |
| `disk_hard_stop` | disk guard at 90% |
| `shutdown` | `SIGTERM` or supervisor stop |
| `spawn_failed` | child could not be started or did not become ready |
| `orphan_reaped` | found by the reaper without a live owner |

### 3.4 Domain circuit breaker (storage is 1.5's; behaviour is 2.9's)

Scope: one breaker per `source` (keyed by `source.domain` = `domain_key`, DC-09). State is in the four `source.breaker_*` columns.

**Window.** The window is the most recent **20 units of the domain that reached a terminal state after the breaker's last reset point** (`breaker_changed_at`). It is read with `recentDomainOutcomes(domainKey, limit)` with a limit larger than 20 (suggested 3 × 20) and then filtered (OQ-2.9-14). Window size 20, trip ratio ≥ 50%, base 6 h doubling to 7 d, half-open with one probe: [Decision] doc 22 §9.

**Classification of window units (P, OQ-2.9-14).**

| Terminal state | Counts as | Note |
|---|---|---|
| `BLOCKED` | failure | doc 22 §9 "failure/`BLOCKED`" |
| `QUARANTINED` (any reason except `LEASE_LIMIT`, `VALIDATION_TIMEOUT`) | failure | the ladder was exhausted on this site |
| `ACCEPTED`, `NEEDS_REVIEW` | success | the site served usable evidence |
| `SKIPPED` | ignored | policy, budget or job closure, not a site health signal (1.4 §3.8) |
| `QUARANTINED` with `LEASE_LIMIT` or `VALIDATION_TIMEOUT` | ignored | infrastructure causes, not the site's |

A unit that is retried manually and later changes state is read in its **current** state [Assumption: `recentDomainOutcomes` reads current rows].

**Open duration.** `open_for = min(6 h × 2^trip_count_before, 7 d)` where `trip_count_before` is the stored `breaker_trip_count` *before* this transition increments it.

| Trip (new `trip_count`) | 1 | 2 | 3 | 4 | 5 | 6 and later |
|---|---|---|---|---|---|---|
| `open_for` | 6 h | 12 h | 24 h | 48 h | 96 h | 168 h (7 d, capped from 192 h) |

**Transition table (every row is one `recordBreakerTransition` call with the expected state and expected `breaker_changed_at` as the compare-and-set guard).**

| # | From | To | Trigger | Guard | Side effects |
|---|---|---|---|---|---|
| DB1 | `closed` | `open` | `capture_unit.finalized` for the domain (via `ev.supervisor`), or the 30 s breaker tick | window holds 20 post-reset units and failures ÷ 20 ≥ 0.5 | `trip_count+1`; `open_until = db_now + open_for`; emit `source.breaker_opened`; log window counts |
| DB2 | `open` | `half_open` | 30 s breaker tick | `db_now ≥ breaker_open_until` | `breaker_changed_at` = now, which resets the window and starts the probe. (wave-3 review) **(P)** emit `source.breaker_half_open` (`domain_key, half_opened_at`) inside the same `tx` as `recordBreakerTransition`, routed by 1.4 to `ev.orchestrator`, so 2.5 resumes the job it paused at DB1 and the single probe unit can be leased (OQ-2.5-11, OQ-1.4-27). Without it the breaker could never close: the scheduler leases only units of `RUNNING` jobs. (The earlier wording "none (no event)" is withdrawn.) |
| DB3 | `half_open` | `closed` | probe resolved as success (§5.4) | the probe attempt started after `breaker_changed_at` | `trip_count = 0` (OQ-2.9-16); `open_until = null`; emit `source.breaker_closed`; window restarts empty |
| DB4 | `half_open` | `open` | probe resolved as failure (§5.4) | as DB3 | `trip_count+1`; `open_until = db_now + open_for` (doubled); emit `source.breaker_opened` |
| DB5 | `closed` | `open` | manual `supervisor breaker open` (OQ-2.9-20) | operator, reason required | as DB1 but window values are the reason text; `trip_count` unchanged by default |
| DB6 | `open` | `half_open` | manual `supervisor breaker probe` | operator, reason required | as DB2 (permits exactly one probe; never closes the breaker directly), including the event (wave-3 review) |
| DB7 | any | unchanged | `recordBreakerTransition` returns `applied: false` (another supervisor won) | — | re-read the source; re-evaluate once; no error (1.5 E-23) |
| DB8 | `open`, `half_open` | unchanged | `capture_unit.finalized` for the domain | state ≠ `closed` | the window is not evaluated; units finishing while open do not count |

There is no `open → closed` transition: the only way back is through a successful probe (doc 22 §9).

### 3.5 Global breaker state machine (P, parameters in OQ-2.9-21)

| # | From | To | Trigger | Guard | Side effects |
|---|---|---|---|---|---|
| GB1 | `closed` | `open` | `reportGlobalCall(name, ok=false)` | N consecutive failures seen by the reporting process (N: OQ-2.9-21) | `trip_count+1`; `open_until = db_now + cooldown`; log; metric |
| GB2 | `open` | `half_open` | any read of the state, or the 30 s tick | `db_now ≥ open_until` | none |
| GB3 | `half_open` | `closed` | `reportGlobalCall(name, ok=true)` from the single probe call | probe admitted | `trip_count = 0` |
| GB4 | `half_open` | `open` | `reportGlobalCall(name, ok=false)` from the probe call | probe admitted | `trip_count+1`; cooldown doubles up to a cap (OQ-2.9-21) |
| GB5 | `closed` | `closed` | `reportGlobalCall(name, ok=true)` | — | the process-local consecutive-failure counter resets |

All writes are compare-and-set on `(state, changed_at)`. A caller seeing `open` skips the dependency (for `object_storage`: `putBlob` spools instead of uploading, 1.3 §4.2). In `half_open`, exactly one in-flight call is admitted as the probe; others behave as if `open`.

### 3.6 Slot and child lifecycle (in memory in the supervisor; not persisted)

A **slot** is one unit of browser capacity. At most `LIMIT_BROWSER_SLOTS` children exist per supervisor ([Estimate] 2–3, doc 22 §6; OQ-2.9-5).

| # | From | To | Trigger | Notes |
|---|---|---|---|---|
| L1 | `NONE` | `SPAWNING` | slot needs a child (first unit of a new session) | pre-flight check that the runtime is healthy before leasing (R9) |
| L2 | `SPAWNING` | `READY` | child sends its ready message within `LIMIT_CHILD_READY_TIMEOUT_S` | `capture_session` row opened |
| L3 | `SPAWNING` | `GONE` | timeout or spawn error | `end_reason = spawn_failed`; lease released as unused (OQ-2.9-10); slot backs off |
| L4 | `READY` | `BUSY` | unit leased and attempt started | one unit at a time per child (DC-07: fresh context per unit is 2.2's) |
| L5 | `BUSY` | `READY` | result handled, evidence committed or failure written, recycle limits not reached | per-unit temp dir removed |
| L6 | `READY` | `ENDING` | 50 units served, or 30 min since spawn, or `job_drained`/`idle` | child asked to shut down; killed after `LIMIT_CHILD_SHUTDOWN_S` if still alive |
| L7 | `BUSY` | `KILLING` | deadline, silence, memory, lease lost, protocol error, disk hard stop, shutdown | `kill -9`, then §5.2 handling |
| L8 | `ENDING`, `KILLING` | `GONE` | child confirmed dead and removed | `capture_session.ended_at`, `end_reason`, `units_served` written |
| L9 | `GONE` | `NONE` | batch directory removed | slot may spawn again |
| L10 | any | `KILLING` | child exits by itself | treated as `crash` / `memory_kill` unless it already sent a result |

### 3.7 Disk guard levels (in memory; the visible state is the `intake_hold` row with `reason = 'disk'`)

| # | From | To | Trigger | Actions |
|---|---|---|---|---|
| D1 | `ok` | `pause` | disk usage ≥ 80% | `holdIntake(disk)`; `flushSpool`; temp cleanup; running units finish (1.4 R17) |
| D2 | `pause` | `stop` | usage ≥ 90% | hard stop: kill every child, `releaseLease(shutdown)` for each running unit (no attempt used); `flushSpool`; alert; no new spawn |
| D3 | `stop`, `pause` | `ok` | usage below the resume threshold (OQ-2.9-25) | `releaseIntake(disk)` |
| D4 | `stop` | `pause` | usage < 90% but not below the resume threshold | children may be spawned again only after D3 (intake hold still open) |

## 4. API Surface

**No HTTP endpoints and no `/internal/*` routes** (F-24). 2.9 is a process (`PROCESS_ROLE=supervisor`, 1.1) plus a TypeScript module **(P name: `services/supervisor`**, directory name per 1.1 §3.1) and CLI subcommands. It owns **no new BullMQ job type**; it consumes one event queue that 1.4 already defines.

### 4.1 Loops in the `supervisor` process

| Loop | Cadence | Does | Basis |
|---|---|---|---|
| Slot loops (one per slot) | continuous; poll interval when nothing is eligible `LIMIT_SUPERVISOR_POLL_S` ([Estimate] 2 s) | §5.1 unit pipeline | DC-03 |
| Watch tick | 1 s [Estimate] | per running unit: child silence, attempt deadline, step budget, heartbeat relay due | doc 22 §5 |
| Resource check | 5 s [Estimate] | child memory vs limit | doc 22 §5 |
| Lease sweeper | 30 s | `runLeaseSweep` (§4.4) | doc 22 §9 |
| Orphan reaper | 60 s | `runReaper` | doc 22 §5, §9 |
| Disk guard | 60 s | `runDiskGuard` | doc 22 §9 |
| Breaker tick | 30 s [Estimate] | DB2 (now emitting `source.breaker_half_open`) and global GB2; half-open probe resolution; DB1 backstop for domains with unprocessed events; (wave-3 review) **(P)** also calls `recordCrawlerSeen` (2.5) while a crawl session runs, so the active-time clock of 2.5 can tell a running session from a stopped or sleeping machine (OQ-2.5-6) | doc 22 §9 |
| Spool flush | 60 s ((P) from OQ-1.3-18) | `flushSpool` (1.3) | OQ-1.3-18 |

### 4.2 Required contract of a capture child (what the supervisor needs; 2.2 owns the implementation)

*(wave-2 review)* Message names here are descriptive. The binding wire names are 2.2's: `ready`, `run_attempt` ("start"), `heartbeat`, `attempt_result` ("result"), `abort`, `shutdown`, `recycle_requested`, `fatal`.

The child is untrusted code in an untrusted-content boundary (doc 15 #9, F-20). The supervisor treats **every child message and file as untrusted input**: schema-validated, size-bounded and never executed. Wire format, transport, and the evidence manifest layout are OQ-2.9-2 (owner 2.2) and OQ-2.9-3. The *requirements* below are fixed by DC-03, DC-07 and 1.4.

| # | Requirement | Basis |
|---|---|---|
| C1 | **Ready message** within `LIMIT_CHILD_READY_TIMEOUT_S` ([Estimate] 30 s) after start | DC-01 |
| C2 | **Start message** (supervisor → child) carries: unit descriptor (`canonicalUrl`, `device_profile` code), `strategy` (S0–S3, chosen by 1.4, never by the child), `attemptId`, the attempt deadline and the step budgets, the active recipe body or none, the effective-policy values the child needs. The child holds **no database or Redis credentials**, so the supervisor reads the recipe and policy and passes them in | DC-05, OQ-1.1-13, 1.5 §4.1 |
| C3 | **Heartbeat messages** (child → supervisor) with the current `capture_step` (`navigate`, `ready`, `capture`, `extract`) at least every 10 s, sent from a timer independent of page progress. A heartbeat proves the process is alive. It does **not** prove progress: progress is judged by step budgets and the attempt deadline | DC-03 |
| C4 | **Exactly one result message** per unit: `outcome` ∈ {`captured`, `failed`, `blocked`, `skipped`}, optional `reasonCode`, small `reasonDetail`, `flags`, `fingerprint`, optional `recycle: true`, and an **evidence manifest** (files with path, raw artifact type, MIME type, size, `meta`) | 1.4 §4.1, 1.3 §3.3 |
| C5 | Result files are placed where the supervisor can read them (OQ-2.9-3). The supervisor, not the child, uploads to R2 and commits to Postgres | OQ-1.1-13, DC-02 |
| C6 | **Shutdown message** honoured: close the browser and exit within `LIMIT_CHILD_SHUTDOWN_S` ([Estimate] 5 s); otherwise it is killed | DC-07 |
| C7 | **Exit when the supervisor channel closes** (defence in depth against a dead supervisor; the reaper is the backstop) | DC-03 |
| C8 | One unit at a time; a fresh browser context per unit; per-unit temp files confined to a per-unit directory. Contents are 2.2's | DC-07 |
| C9 | No detached processes that outlive the container; no outbound traffic except through the sandbox's restricted egress | F-20, 1.7 |
| C10 | The child never decides retries, rung, backoff, or breaker behaviour, and never evades blocking: no proxy rotation, no fingerprint spoofing, no CAPTCHA solving | DC-05, DC-08, SC-03 |
| C11 | S3 (non-browser HTTP fallback) runs inside the same kind of child with the same limits (OQ-2.9-33) | doc 22 §7 |

## 5. Business Rules & Edge Cases

### 5.1 The unit pipeline (sequence)

```
slot loop (per slot, while not shutting down):
  if child is None:
      if not runtime.healthy(): back off; continue                       # R9, before leasing
      lease = leaseNextUnit({ leaseOwner })                              # unscoped: fair across domains
  else:
      lease = leaseNextUnit({ leaseOwner, captureJobId: session.jobId }) # scoped to the session's job (F-21)
  if lease is null: (linger rules OQ-2.9-6) ; sleep POLL; continue
  if child is None: spawn child; openCaptureSession(lease.jobId); on failure releaseLease(unused); back off

  wait = paceDomain(lease.domainKey)                                     # R10
  sleep(wait)                                                            # unit is LEASED; TTL 60 s (OQ-2.9-9)
  a = startAttempt({ unitId, leaseId, captureSessionId })                # T4; attempt deadline = now + 90 s (DB clock)
  t0 = monotonic()                                                       # local kill deadline = t0 + 90 s
  send start{ unit, strategy, attemptId, deadlines, recipe, limits } to child
  while no result and no kill condition:                                 # watch tick 1 s
      child heartbeat message  -> relay heartbeat({ step }) (at most every 10 s; immediately on step change)
      now > t0 + 90 s          -> kill; expireLease(deadline_exceeded)
      step over budget         -> kill; completeAttempt(failed, DEADLINE_KILLED, {step})
      child silent >= 60 s     -> kill; expireLease(heartbeat_lost)
      rss >= limit             -> kill; completeAttempt(failed, MEMORY_KILLED)
      heartbeat() threw LeaseLost | DeadlineExceeded -> kill; do not write (or expireLease for DeadlineExceeded)
  on valid result:
      step = upload; for each manifest file: putBlob(signal = min(30 s, time left in the attempt))
      withLease({ unitId, leaseId }, tx => { registerRawArtifact(tx, ...) for each file; completeAttempt(..., tx) })   # T7–T12 in one commit
  remove per-unit directory; units_served += 1
  if units_served >= 50 or age >= 30 min or child asked recycle: end session (recycled_*)
```

Heartbeat relay stops while the supervisor is uploading *only if* the child is already gone; the supervisor then heartbeats from its own timer under `step = upload` so the lease stays valid until `attempt_deadline_at` (R6 of 1.4 still caps it). (wave-3 review) The files registered in the `withLease` transaction are exactly the list `interpretAttemptResult` returns (2.2 §4.6): for every artifact `meta.role` and (for screenshots) `meta.pass` are copied from the manifest into `raw_artifact.meta`, and the attempt's `result.json` is registered as a `LOG` artifact with `meta.role = 'attempt_result'`, so 2.10's checks and 3.2 find their inputs from the registry alone (OQ-2.2-31, OQ-2.10-4).

### 5.2 Outcome handling table (what the supervisor writes for each observation)

| Observation | Detection | Kill? | Call into 1.4 | Session | Basis |
|---|---|---|---|---|---|
| Result `captured`, evidence stored | valid result; uploads ok | no | `completeAttempt(captured)` inside `withLease` (T7) | continues | DC-02, doc 22 §5 |
| Result `failed` | valid result | no (unless `recycle`) | `completeAttempt(failed, reasonCode from child)` (T8/T9) | continues | 1.4 §4.1 |
| Result `blocked` | valid result | no | `completeAttempt(blocked)` (T10/T11); no evasion, no immediate retry here | continues | DC-08, 1.4 R10 |
| Result `skipped` | valid result | no | `completeAttempt(skipped)` (T12) | continues | 1.4 T12 |
| Result invalid (schema, size, path, type) | validation | yes | `completeAttempt(failed, RESULT_INVALID)` | ends `protocol_error` | DC-01, doc 15 #9 |
| Upload fails (not a full disk) | `putBlob` error, `StorageUnavailable` | no | `completeAttempt(failed, UPLOAD_FAILED)` | continues | 1.3 §4.2 |
| Upload refused: `SpoolFull` | 1.3 error | yes if disk level `stop` | `releaseLease(shutdown)` (attempt not counted, OQ-2.9-11) | ends `disk_hard_stop` | 1.3 E4, doc 22 §9 |
| Attempt deadline (90 s) reached | local timer (conservative: from request send); or `heartbeat` throws `DeadlineExceeded` | **kill -9** | `expireLease(deadline_exceeded)` (T8/T9) | ends `deadline_kill` | DC-03, F-32 |
| Step budget exceeded | local step timer | **kill -9** | `completeAttempt(failed, DEADLINE_KILLED, {step, budget})` (OQ-2.9-12) | ends `step_deadline_kill` | doc 22 §5 |
| Child silent for 60 s | monotonic timer | **kill -9** | `expireLease(heartbeat_lost)` | ends `heartbeat_lost` | DC-03 |
| Memory ≥ limit, or runtime reports OOM kill | resource check or `exited().oomKilled` | **kill -9** if still running | `completeAttempt(failed, MEMORY_KILLED)` | ends `memory_kill` | DC-07 |
| Child exits with no result | `exited()` | already dead | `completeAttempt(failed, CRASHED)` | ends `crash` | doc 22 §2 #3 |
| `LeaseLost` from `heartbeat`/`withLease`/`completeAttempt` (lease expired or revoked by `closeUnits`) | exception | yes | none: the write is refused by design; log | ends `lease_lost` | 1.4 R3, T25 |
| No successful `heartbeat` for 60 s (Postgres or network down) | monotonic timer from last success | yes, all children | none possible; leases expire (1.4 E3/E10) | ends `db_unreachable` | 1.4 R5 |
| `SIGTERM` | signal | per §5.9 | `releaseLease(shutdown)` for unfinished units (T13) | ends `shutdown` | 1.4 E24, 1.1 §4.2 |
| Disk level `stop` | disk guard | yes, all children | `releaseLease(shutdown)` per running unit | ends `disk_hard_stop` | doc 22 §9 |
| Spawn fails or child never ready | timeout | yes | `releaseLease(unused)` (T5) | `spawn_failed` | OQ-2.9-10 |

Order rule: **kill first, then write to Postgres**, so a child can never act after its unit is already requeued (defence in depth; the child has no DB credentials anyway).

### 5.3 Core rules

| # | Rule | Basis |
|---|---|---|
| R1 | **The capture code is never trusted to time itself out.** Every attempt has a supervisor-enforced hard deadline and every step a budget; expiry means `kill -9`, not a polite abort. The deadline is also passed into the child so it can exit cleanly first | DC-03, doc 22 §5 |
| R2 | **A heartbeat proves liveness, not progress.** Progress is bounded by step budgets and the 90 s attempt deadline. Silence for 60 s kills the child even if its step budget is not over | DC-03 |
| R3 | **The supervisor relays; the child never writes state.** Only the supervisor holds database, Redis and R2 credentials; the child holds none | OQ-1.1-13, 1.1 §3.5, doc 15 #9 |
| R4 | **All writes for a unit go through 1.4 functions under the current `lease_id`**; evidence registration and `completeAttempt` happen in one `withLease` commit. A supervisor that has lost its lease writes nothing | 1.4 R3, DC-02 |
| R5 | **Blob first, row second.** Evidence is uploaded (or spooled) before the registry rows are committed; a crash between the two leaves only an orphan blob for 1.3's GC | DC-02, 1.3 R4 |
| R6 | **No child is ever left unsupervised.** If the supervisor cannot reach Postgres for 60 s, it kills its children (self-fence). If it dies, children exit on channel close (C7) or are reaped at the next start | 1.4 R5, DC-03 |
| R7 | **Kill means `kill -9` plus confirmation.** The child is confirmed dead within `LIMIT_KILL_CONFIRM_S`; if not, kill is retried once and the supervisor stops spawning in that slot, logs, and raises an alert through 1.8 | DC-03, DC-01 |
| R8 | **Fresh process per session, fresh process after any kill or crash, never a reused browser after an unexplained failure.** Recycling is hygiene only and is never used to retry a block | DC-07, DC-08 |
| R9 | **Check the runtime before leasing.** A slot leases only after `ChildRuntime.healthy()`; spawn problems must not burn units' lease budgets (1.4 `lease_count` bound) | 1.4 OQ-1.4-6, OQ-2.9-10 |
| R10 | **Pace before the attempt.** `paceDomain` is called after the lease and before `startAttempt`; a unit never waits inside `RUNNING` for pacing. If the wait would exceed half the lease TTL (30 s), the lease is released as unused (OQ-2.9-9) | F-10, 1.4 OQ-1.4-19 |
| R11 | **Session = one job.** The first unit of a session is leased unscoped (fair across domains); later units in the session are leased with `captureJobId` so a session never mixes jobs | F-21, 1.4 §4.1 |
| R12 | **Recycle at 50 units or 30 min**, checked between units; a unit in progress is never cut short for recycling | DC-07 |
| R13 | **Memory:** the runtime limit (≈ 2.5 GB) is the hard wall; the supervisor's 5 s RSS check kills just before it so the reason code is `MEMORY_KILLED` not `CRASHED` | doc 22 §5 |
| R14 | **Treat child output as untrusted.** Result messages and manifest files are schema-validated; file paths must resolve inside the batch directory with no symlinks; sizes obey 1.3's per-type limits (R10 of 1.3); counts are capped (OQ-2.9-2) | doc 15 #9, DC-01 |
| R15 | **Breakers react to outcomes, never to feelings.** The domain breaker window uses terminal unit states from Postgres (§3.4); it is recomputed from Postgres every time, so losing Redis or restarting the supervisor loses nothing | DC-14, doc 22 §9 |
| R16 | **A blocked site stays blocked.** The breaker only *stops* traffic and permits one probe after the cooldown. No code path shortens the cooldown, rotates IP/proxy, changes the user-agent or fingerprint, or retries a block more than 1.4's single polite retry. ### 5.4 Half-open probe resolution (P, OQ-2.9-15)

A probe is the **first attempt started in the domain after the breaker entered `half_open`** (`capture_attempt.started_at > breaker_changed_at`). The breaker tick resolves it:

| Probe attempt | Resolution |
|---|---|
| `outcome = captured` and the gate verdict (`verdict`) is `ACCEPTED` or `NEEDS_REVIEW` | success → DB3 |
| `outcome ∈ {blocked, failed, deadline_exceeded, lease_expired}`, or `captured` with verdict `REJECTED` or `BLOCKED` | failure → DB4 |
| `outcome ∈ {released, revoked}`, or `skipped` | not a probe: ignore and wait for the next attempt |
| `captured` and no verdict by the validation deadline (OQ-1.4-7) | failure → DB4 |

The first resolved attempt wins; later attempts do not change the decision. 1.4's half-open admission counts only `LEASED` + `RUNNING` units, which can admit a second unit while the probe is in `RETRY_WAIT`, `CAPTURED` or `VALIDATING`: OQ-2.9-15.

### 5.5 Lease sweeper behaviour (every 30 s)

| Step | Action | Basis |
|---|---|---|
| 1 | Select `capture_unit` rows with `state IN (LEASED, RUNNING)` and `lease_expires_at < now` (index `lease_expires_at`, 1.4 §3.5) | DC-03 |
| 2 | For each, call `expireLease({unitId, leaseId, cause: 'heartbeat_lost'})`. `LEASED` → T5 (no attempt used); `RUNNING` → T8/T9. The call is conditional on `leaseId`; a stale call is a no-op | 1.4 §4.1 |
| 3 | **Overdue backstop:** select `RUNNING` units with `attempt_deadline_at + LIMIT_WATCHDOG_GRACE_S < now` still holding a lease; call `expireLease(cause: 'deadline_exceeded')`. 1.4 R6 already stops lease extension past the deadline, so this only shortens the worst case from 150 s to ≈ 100 s | doc 22 §9 (janitor "RUNNING beyond hard deadline"), 1.4 R6 |
| 4 | If `expireLease` returns `killChild = true` **and** the unit's `lease_owner` is this instance, kill that child now. If the owner is another instance, do nothing: that instance's own `heartbeat`/`withLease` will fail with `LeaseLost` within 10 s and it will kill its child | 1.4 §4.1 |
| 5 | If the owner is this instance but no child is registered for the unit, log `orphan_lease`; the reaper handles any container | doc 22 §9 |
| 6 | Record counts and `last_tick_at` | doc 22 §12 |

The sweeper runs **inside the `supervisor`** (wave-2 review: not also in `worker-app`; the reconciler in `worker-app` is the 5-minute backstop for a dead crawler machine, 1.4 §5.4 step 3; OQ-2.9-24). It is cheap and idempotent, so adding a `worker-app` copy later, once the database is online, needs no code change (OQ-2.9-40). The 2.5 janitor owns job-level roll-up; the sweeper owns unit-level expiry.

### Reliability

- A unit's worst-case time in `RUNNING` is 90 s deadline (+ ≈ 10 s sweeper grace); even if the supervisor and its kill both fail, 1.4 R6 caps it at 150 s.
- Losing Redis, the supervisor, or a child loses at most one attempt (DC-03, DC-14).
- Every loop is idempotent, bounded and independent (R21, R23).
- Breaker and poison state live in Postgres and survive restarts (DC-14).
- Kill-then-write ordering and lease-conditional commits prevent a unit from being captured twice (DC-02).

| Property test with 1.4 | with random child faults, no unit holds two leases, no zombie write commits, and every unit ends in a terminal state within its deadline |

### Assumptions

- [Assumption] (F-45) The crawler machine is a normal desktop or laptop operating system with a container runtime; the spec does not depend on which one, and the OS-specific mechanisms (keep-awake, process priority) are chosen when building.

- [Assumption] The supervisor is a separate process in the same codebase and belongs to the `worker` deployable (1.1; doc 22 §15 #5).
- [Assumption] One supervisor instance runs per crawler machine host; the instance id changes at every start (§3.3).
- [Assumption] Capture children are created by the supervisor, are not tied to the supervisor container's lifetime, and are labelled so they can be found after a supervisor crash (§4.3).
- [Assumption] The capture child holds no Postgres, Redis or R2 credentials; the supervisor uploads and commits (OQ-1.1-13 suggested default, 1.4 assumption).
- [Assumption] `recentDomainOutcomes` and the `capture_unit` indexes listed for 2.9 in 1.4 §3.5 are readable by the supervisor; reading them needs no extra contract.
- [Assumption] All lease, deadline, breaker and age comparisons that are stored use the Postgres clock; process-local kill timers use a monotonic clock (1.4, OQ-1.1-21).
- [Assumption] `capture_unit.finalized` events reach `ev.supervisor` at least once and in any order (1.4 §4.4); the breaker evaluation is a pure function of Postgres state plus compare-and-set, so duplicates and reordering are harmless.
- [Assumption] Window units are read in their current state (a manually retried unit that later succeeds counts as a success).
- [Assumption] Numbers in doc 22 §5 and §9 that are not tagged `[Decision]` above (slots, memory, step budgets, cadences) are starting values to be calibrated in the 20-site spike (doc 22 header, E2).
- [Assumption] A wave-3 janitor in 2.5 will use `closeUnits` and `expireLease` as 1.4 describes; 2.9's sweeper does not replace job roll-up.
