# 1.2 Core Data Platform: Task List

Source: [1.2 spec](../1.2-core-data-platform.md) · decisions applied: F-18, F-21, F-23, F-26, F-31, F-35, F-45, F-55 · status: draft

**How to read this list.** Before launch (F-55) the database is a Postgres with pgvector running on the founder's computer from `compose.dev.yml` (1.1-T21). Groups G1 to G5 are that local-first path. G6 is the move to the online database and is built only **when the library goes online**. The spec has no F-47 to F-64 decision that settles one of its open questions, so every open question it still has is used below with its suggested default and tagged. Task ids are stable; new tasks take the next free number.

Migration order is fixed by the wave-1 review: extensions, `device_profile`, 1.5 tables, 1.4 tables, 1.3 tables, the 1.2 graph tables, then 1.6, 4.3, 4.5, 5.1. Tasks that create tables with foreign keys name the other Part's migration they wait for.

## Not in V0
- `screen_state`, `component`, `interaction`, `flow`, `flow_node`, `flow_edge` tables: created by their first consuming Part (2.7, 4.9 in V1; 7.6, 7.8 in V2); only the reserved `entity_type` names exist (§3.7). Not even the values are accepted by T20 until then.
- `section.screen_state_id` (V1) and `screen.page_id` nullable for mobile (V2): added by the migration that needs them (§3.7).
- `device_profile` row `tablet` and theme, locale, orientation columns: V1, 2.8 (§3.7).
- `design_tokens` columns on `product_version`, `page`, `section`: V1, added by 4.8's migration (F-21).
- Ownership columns for private user uploads: V1, 6.5 (§3.7).
- Native `uuidv7()` default in the database: only a fallback if the chosen version has it (OQ-1.2-3); the application generates ids.
- Reversing a `withdrawn` status through an explicit logged admin action (OQ-1.2-18 suggested default): not built; `setPublishStatus` refuses it. 6.4 and 2.10 raise it if needed.
- Denormalized label columns (`section_type`, `page_type`) and denormalized provenance columns (OQ-1.2-15, OQ-1.2-16): not created; 1.6 adds provenance columns only if a query needs them.
- Public visibility of assets and animations (R15, OQ-1.2-17): none in V0.
- Managed database, read replica, external pooler (F-35 section 5 triggers).
- Gate values on graph rows: written by 2.10's `applyGateToGraph` (called by 3.2 inside `recordScreenGraph`'s transaction), not by this Part (§3.8).
- Row creation logic for the graph (which rows exist for a unit): 3.2.
