# 2.4 Media Extraction & Animation Capture: Task List

Source: [2.4 spec](../2.4-media-extraction-animation-capture.md) · decisions applied: F-59 (still preview for every animated item, playable video only for videos and GIFs, no canvas clip), F-63 (downloaded originals kept as raw evidence, derived previews deleted first), F-45, F-46, F-10, F-13, F-18, F-20 · status: draft

**Reading notes.** All 2.4 work in the capture child lives in `services/media-service/extract/` and has no database, storage or queue access (2.2 R2); everything that needs them (derive step, reader) lives in `services/media-service/derive/` or the reader. "GIF" in F-59 is read as the spec's `animated_image` kind (GIF, APNG, animated WebP/AVIF, §3.4): these and `video` are the only kinds that get a `normalized_video`. Cross-Part dependencies name the other Part's task by description where its number is not known yet (`<part>: <what>`); replace with `<part>-Tnn` when that list is published. Fixture ids are 2.11's (§5.4.7 and §5.4.11 of the harness spec). Unit-level checks without a fixture id stay with 2.4 (2.11 §5.9).

## Not in V0
- Scroll-pass video recording and the `screen_artifact` role for it: V1 (F-13, F-40); only `scroll_pass_eligible` and `motion_libraries` are computed (T38). Spec §3.9, R31, OQ-2.4-28.
- Canvas/WebGL clip recording and any `normalized_video` for canvas: not built in V0; canvas keeps a still (F-59, OQ-2.4-4 decided). A raw `VIDEO` artifact is reserved for V1.
- Playable (`normalized_video`) versions of Lottie and animated SVG: later, if the founder wants them (F-59); a pinned Lottie player and isolated renderer are not built. Their original and live still are kept (T34, T41).
- Interaction-triggered motion (hover, menus, modals, tabs, accordions, carousel controls): V1, 2.7 (F-02). Declared transitions only are recorded.
- Computer-vision models in the visual layer and screen-recording fallback: pixel difference only (T26, OQ-2.4-29).
- Fonts (4.8), `og:image` and favicons (2.3's DOM capture), audio, PDFs and documents, sprite slicing and image-sequence assembly: not collected or only hinted (OQ-2.4-25).
- Perceptual duplicate detection (3.1), classification of media roles (4.3), OCR (4.2), embeddings (4.5), library fingerprinting beyond the motion libraries (4.7), pixel-level redaction (V2): other Parts.
- Public display, thumbnails, CDN delivery and the animation viewer: 6.1, 6.6 (F-18); nothing 2.4 stores is public (R23).
- Hash-skip on re-crawl: 3.4, after capture (A15).
- Creation of `asset`, `animation` and `animation_artifact` rows and `asset.source_url` query redaction: 3.2 (with 3.3's patterns); 2.4 only supplies the manifest and the `capture_unit.media_derived` event (T16, T48).
- `asset-service` listed in doc 02: not used in V0 (A16).
