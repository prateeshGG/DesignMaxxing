# 1.3 Object Storage & Artifact Registry: Task List

Source: [1.3 spec](../1.3-object-storage-artifact-registry.md) · decisions applied: F-18, F-33, F-45, F-47, F-49, F-51, F-52, F-55, F-63 · status: draft

**How to read this list.** Before launch (F-55) every blob is a file on the founder's computer, written through the same `packages/storage` interface that will later talk to Cloudflare R2 (F-51). A file written to the local disk with `fsync` and an atomic rename is the first durable write (F-47), so the spool is not needed until R2 is in use. The Drive desktop folder is the backup before launch and needs no code (F-51); the only requirement on this Part is that the synced folder never contains a half-written file and never has a file rewritten in place, which the content-addressed layout and the temp-then-rename write already give. Groups G1 to G7 are that local-first path. G8 is the R2 path, the spool and the move online, built only **when the library goes online**. Task ids are stable; new tasks take the next free number.

The registry tables follow 1.2's conventions for every Part (`text` plus `CHECK` instead of a native enum, snake_case singular names, `RESTRICT` foreign keys). The spec writes "enum `raw_artifact_type`"; the tasks use `text` plus `CHECK` with the same values.

## Not in V0
- Lifecycle rules and storage tiering, including the 90-day cold move and the 180-day recording expiry (F-33, OQ-1.3-12): they switch on at V1 when recordings exist; no task.
- `APP_PACKAGE` use (V2 hook): only the allowed value in the `type` CHECK exists (T07).
- Null `capture_attempt_id` for `USER_UPLOAD` sources (V1 hook): the column is nullable; no behaviour, no task.
- A quarantined layer for unredacted authenticated captures (V2 hook, F-19): the `raw/` prefix leaves room for it (§7.3).
- Multipart upload: every blob is below the size cap (§7.1 assumption).
- Automatic requeue after a lost spool (OQ-1.3-17): alert only (T24); the operator re-runs the units through 1.4.
- A `raw_artifact.stored` event after a spool flush (OQ-1.3-3): revisit if long outages produce many dead-lettered jobs.
- A parent column for derived-from-derived artifacts (OQ-1.3-8): not built.
- Public image URLs, CDN delivery and cache purge: 6.1; the admin Storage view and takedown screen: 6.4; retention as a legal document: 8.2.
- Guard against mass reprocessing reading raw evidence (R18): enforced by the reprocessing initiator, not by this Part.
- A Drive upload tool or Drive-based storage driver: the Drive desktop folder is a founder-side backup with no code (F-51); Drive's API is not used for serving or storage.
- Backup content, schedule and restore test: 1.7.
