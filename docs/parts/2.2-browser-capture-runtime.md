## 1. Purpose & Scope

**Purpose.** 2.2 is the **capture child**: the process that the supervisor (2.9) starts, feeds one attempt at a time, watches and kills. For one attempt of one `CaptureUnit` it builds a deterministic, sharp browser environment for the unit's device profile, navigates politely and honestly, decides when the page is visually ready, runs the strategy rung the attempt was given (S0–S3), applies the site's recipe, calls the page-capture module (2.3) and the media module (2.4) in a fixed order inside a fixed budget, and hands back a result manifest plus files. It never decides what is publishable (2.10), never touches Postgres, Redis or object storage, and never discovers sites or pages (F-46, F-10).

**Phase:** `[V0]`. Later-phase hooks are marked **[hook]** and are compatibility only (F-40).

### 3.6 Child process states (not stored)

```
STARTING ──ready──► IDLE ──run_attempt──► ATTEMPT ──attempt_result──► IDLE ──shutdown──► EXITED(0)
   │                  │                      │ │
   └─fatal(10)        └─stdin closed──► EXITED(0)   │ └─recycle_requested──► (supervisor shuts it down)
```

Inside `ATTEMPT` the phases follow the step enum: `navigate → ready → capture → extract` (the `upload` and `validate` steps are the supervisor's and 2.10's; the child is finished when it sends `attempt_result`).

## 4. API Surface

**No HTTP endpoints and no events** (F-24: no `/internal/*`; events are 1.4's). 2.2 exposes (a) the child protocol, (b) supervisor-side library functions, (c) in-child module contracts, (d) configuration keys, (e) a standalone mode.

### 4.1 Launch and process contract

| Item | Contract |
|---|---|
| Launch | 2.9 starts one container per **slot** from the `worker` image with `PROCESS_ROLE=capture-child` (mechanism: OQ-1.1-12). The container gets no `DATABASE_URL`, `REDIS_URL` or `R2_*` (1.1 matrix; OQ-1.1-13), restricted egress and the sandbox profile (F-20, 1.1 R15, 1.7) |
| Config | Validated at startup (1.1 R8): `PROCESS_ROLE`, `LOG_LEVEL`, `RELEASE_SHA`, `LIMIT_*`, `CAPTURE_*` (P). Missing or invalid key → exit 10 with key names only |
| Concurrency | One browser, **one attempt at a time** per child [Assumption A1]; two concurrent units of one domain are two children (F-10) |
| Volume | A per-batch volume mounted at `/batch` is the only writable path besides tmpfs; the child writes `output_dir` there; 2.9 reads, uploads, then deletes the attempt folder (doc 22 §5 "temp dirs deleted on unit end") |
| Lifetime | Fresh process per batch, recycled by 2.9 after 50 units or 30 min (DC-07). The browser is reused across attempts of the batch, the context never is (R1) |

### 4.2 Child protocol (transport and framing: OQ-2.2-2; suggested NDJSON on stdin/stdout)

Every message is one JSON object with `type` and `schema_version`. **stdout carries protocol messages only**; page console output and logs go to stderr as structured lines carrying the `log_context` fields (1.4 `logContext`; logger format is 1.8's).

| Direction | `type` | Payload | Rules |
|---|---|---|---|
| child → sup | `ready` | `{child_id, node_version, playwright_version, chromium_version, crawler_version, host_os, image_digest, started_at}` | Sent once after Chromium has launched. 2.9 waits a bounded time for it (value 2.9's) |
| sup → child | `run_attempt` | `AttemptInput` | Only valid in `IDLE`; otherwise exit 12 |
| child → sup | `heartbeat` | `{attempt_id, step: CaptureStep, substep?: string, progress: int, step_elapsed_ms, attempt_elapsed_ms, node_rss_mb}` | Every `heartbeat_interval_ms` (10 s, DC-03) **and** immediately on every step change; `progress` increases whenever a sub-operation completes. 2.9 relays `step` to 1.4 `heartbeat` (T6); `substep` is for logs only. Sent from the same event loop that runs capture code, so a blocked loop stops heartbeats and the lease expires (DC-03) |
| sup → child | `abort` | `{attempt_id, reason}` | Cooperative stop: fires the root `AbortSignal`; the child must finish cleanup and send `attempt_result` (`failed`, `TIMEOUT`) within 5 s [Estimate], else 2.9 kills it. 2.9 may skip `abort` and kill directly (DC-03) |
| child → sup | `attempt_result` | `AttemptResult` | Exactly one per `run_attempt`; the only way an attempt ends cleanly |
| child → sup | `recycle_requested` | `{reason}` | Sent after any attempt that ended by abort, crash, page crash or context-close failure (A6); 2.9 decides |
| sup → child | `shutdown` | `{}` | Child closes the browser and exits 0; also on stdin close and SIGTERM (5 s [Estimate]) |
| child → sup | `fatal` | `{code, message}` | Followed by exit with the matching code |

### 4.3 Exit codes (P; interpretation of kills stays with 2.9)

| Code | Meaning | Supervisor reading |
|---|---|---|
| 0 | Clean shutdown (command, stdin closed, SIGTERM) | Normal end of session |
| 10 | Startup failure: invalid config or Chromium would not launch | Do not respawn in a tight loop (2.9 policy) |
| 11 | Browser crashed or disconnected and the child cannot continue | If an attempt was running: `failed`, `CRASHED` |
| 12 | Protocol violation (bad message or schema) | Bug; stop the slot, alert |
| 13 | Abort grace expired: cleanup did not finish, child exits itself | `failed`, `TIMEOUT` |
| 14 | Local I/O failure on `/batch` (write error, disk full) | Disk guard (2.9); attempt `failed` |
| 137 / SIGKILL | Killed from outside (deadline, memory limit, reaper) | 2.9 maps to `DEADLINE_KILLED` / `MEMORY_KILLED` (1.4 §3.11) |

### 4.4 In-child orchestration (the attempt)

**Module slots** (P; 2.3 and 2.4 name their own functions; 2.2 fixes only the shape):

```ts
interface AttemptContext {
  input: AttemptInput;
  page: Page;                       // the single page of this attempt's fresh context
  signal: AbortSignal;              // per-call child of the root signal, already limited to the step budget
  budget: { remainingMs(): number };// monotonic
  networkLog: NetworkLog;           // read-only view: requests, responses, failures, sizes
  passes: PassController;           // enterStatic() / exitStatic() / freezeTransitions()
  awaitReady(opts?: { reason: string }): Promise<ReadinessReport>;
  stability: StabilityProbe;        // cheap "did pixels/layout change in the last N ms"
  recipe: { ignoreSelectors: string[] } ;
  strategy: 'S0'|'S1'|'S2'|'S3';
  heartbeat(step: CaptureStep, substep?: string): void;
  output: { dir: string; add(artifact): void };   // registers a file into the manifest
}
type ModuleResult = { status: 'ok'|'partial'|'failed'|'timeout'|'skipped'; flags?: string[]; detail?: object };
// 2.3: capturePage(ctx, mode: 'full' | 'viewport_steps'): ModuleResult     (slot: pageCapture)
// 2.4: extractMedia(ctx): ModuleResult                                     (slot: media)
```

**Call order for strategies S0–S2** (one attempt; caps are decided numbers, doc 22 §5; budget division: OQ-2.2-5):

| # | Step label | Work | Owner | Cap / budget |
|---|---|---|---|---|
| 1 | `navigate` | Create context + page with the §3.2 options; attach listeners (network, console, page error, dialog, popup, download, `framenavigated`); install the in-page probes with `addInitScript` (layout shift, mutations); install route guards (R7–R9, R14); apply S1+ blocking; one `goto` | 2.2 | navigation 30 s (`LIMIT_STEP_NAVIGATE_S`) |
| 2 | `ready` | `awaitReady` (§5.2) | 2.2 | 15 s cap (F-11) |
| 3 | `ready` | Recipe actions in order: `cookie_dismiss_selectors` clicks, `wait_for_selector` (inside the cap), then `extra_wait_ms` (inside the attempt budget, not the cap); then S1+ consent dismisser; then `awaitReady` again if anything was clicked | 2.2 | bounded by the same 15 s readiness budget except `extra_wait_ms` |

### 4.5 The ladder in one attempt

The child is stateless between attempts: 1.4 chooses the rung (DC-05; a manual retry may start at any rung); the child only executes the rung it is told (R3).

### 4.6 Supervisor-side library (called by 2.9; boundary: OQ-2.2-3)

## 5. Business Rules & Edge Cases

### 5.1 Rules

| # | Rule | Basis |
|---|---|---|
| R1 | **One fresh browser context and page per attempt**, closed in `finally`; no cookies, cache, storage or consent state carries from one attempt to the next. A context that will not close within 5 s [Estimate] ends the child (exit 13) | DC-07, IF§8 |
| R2 | The child **never connects** to Postgres, Redis or R2, holds no secrets, and writes only under `/batch` and tmpfs | F-20, 1.1 matrix, OQ-1.1-13 |
| R3 | **Stateless and idempotent:** the same `AttemptInput` produces an equivalent result; the child remembers nothing about earlier attempts of the unit | DC-02, DC-05 |
| R4 | Every wait is bounded by the step cap **and** the remaining attempt budget (whichever is smaller) and receives an `AbortSignal`; no unbounded loop exists | DC-01, DC-03 |
| R5 | Heartbeats come from the event loop that runs capture code, include the current step, and are sent every 10 s and at every step change | DC-03, 1.4 §4.1 |
| R6 | The child does not enforce its own death: the supervisor's kill is authoritative; the child's `AbortSignal` only allows clean exits | DC-03 |
| R7 | **Exactly one top-level navigation per attempt** (the canonical URL). The child never follows links, never submits forms, never visits a URL it was not given. Site choice and page choice are not the child's (F-46, 2.1) | F-10, F-46 |
| R8 | **Same-registrable-domain rule:** every top-level navigation hop (redirects, and any later main-frame navigation by script or meta refresh) is checked against `source_domain`; a hop to another registrable domain is aborted before its document loads → `skipped`, `OFF_DOMAIN_REDIRECT` (OQ-2.2-21). Reason: the other domain has its own source, policy, takedown and deny-list state (1.5 R-1, R-9; F-41); it may be a competitor library or a site nobody approved (F-46). Same-site subdomains (`www`) are allowed (OQ-1.5-11) | 1.5 R-1/R-9, F-41, F-46 |
| R9 | **Robots on navigation:** each top-level navigation hop's path+query is matched with 2.1's matcher against the stored rules for our user-agent; disallowed (and no `override_active`) → `skipped`, `ROBOTS_DISALLOWED`. Subresources are not matched in V0 but any that robots would disallow is recorded in the network metadata (OQ-2.2-27) | F-10, 1.5 R-4 |
| R10 | **Honest identity:** the context user-agent is the string from `getEffectivePolicy`, unchanged. Forbidden: user-agent or header spoofing, masking `navigator.webdriver`, removing automation flags, patching plugins/languages/WebGL vendor, proxies or IP rotation, CAPTCHA solving, TLS impersonation. Client Hints and every other fingerprint stay as Chromium produces them | F-10, DC-08, SC-03, 1.5 R-5/R-6 |
| R11 | Locale, timezone, colour scheme, viewport, DPR and mobile emulation are **capture-context declarations**, set identically for every site and recorded in `CaptureContext`; they are never varied per site to defeat a block. (Whether this counts as "fingerprint spoofing" is confirmed in OQ-2.2-8/-10) | WF§9, DC-08 |
| R12 | **Reading animation state precedes the freeze:** any extraction that reads animation/transition computed values or animation objects runs in the motion state. `PassController.exitStatic()` must restore it (remove the freeze style, reset emulated reduced motion) before step 5 | DC-20, doc 08 |
| R13 | **No evasion on blocks:** 403/429/challenge ends the attempt `blocked`; the polite retry and breaker are 1.4's and 2.9's. A 429 `Retry-After` value is recorded in `reason_detail`, not used to sleep | DC-08, doc 22 §7, 1.4 R10 |
| R14 | **SSRF check on navigation:** every top-level hop target (and S3 fetch target) is checked with 1.7's guard (private, loopback, link-local, metadata ranges; re-checked after redirects) → `skipped`, `POLICY_DENIED`, detail `ssrf`. Container egress rules are the second layer | F-20 |
| R15 | **Interactions in V0 are only:** scrolling (inside 2.3), the consent dismisser, and recipe `cookie_dismiss_selectors`. Each click target comes from the pattern file or the recipe, never from page text; any resulting top-level non-GET navigation is aborted [Assumption A13]. Everything else defaults to DO NOT EXECUTE | F-16, principles, OQ-1.5-29 |
| R16 | Permission prompts are suppressed (geolocation, notifications, camera, microphone denied); JS dialogs (`alert/confirm/prompt/beforeunload`) are dismissed; new pages from `window.open`/`target=_blank` are closed (bounded by `max_open_pages`); downloads are refused and files deleted; service workers blocked [Assumption A7]; HTTPS errors are failures, never ignored | F-17, doc 22 §5 |
| R17 | The child writes **evidence and context, not judgments:** it records status, readiness, overlays, flags; it never scores, classifies or decides publishability | DC-06, DC-10 |
| R18 | **Failures keep their evidence:** artifacts finished before a failure stay in the manifest; for `failed`/`blocked` attempts with a live page the child makes a bounded diagnostic capture (OQ-2.2-22) | OQ-1.4-22, doc 22 §8 check 3 |
| R19 | Network metadata records URL, method, status, resource type, sizes, timing, failure text and an **allowlist** of header names; never cookies, `Authorization`, or request bodies | F-19 spirit, F-15 |
| R20 | The tracker list never contains font hosts or first-party hosts: a blocked font host fails silently and renders fallback fonts | [Field observation] capture.md "Fonts" |
| R21 | `ignore_selectors` elements are excluded from stability and overlay measurements and passed to 2.3; they are never hidden or removed (evidence preserved) | MB§60, OQ-2.2-18 |
| R22 | A recipe changes behaviour only through the five v1 fields; it cannot add scripts, headers, proxies, robots or rate overrides (1.5 forbids them; the child also ignores unknown keys in a defensive second check) | 1.5 §3.3, DC-08 |
| R23 | The static pass is a **view**, not a different page: same navigation, same URL, same attempt. Large motion-vs-static differences are a gate signal (2.10), never a reason for the child to prefer one | DC-20 |
| R24 | After `abort`, crash, page crash or a context that would not close, the child sets `recycle_requested` | DC-07, A6 |
| R25 | Capture always runs inside the pinned `worker` container image, on the founder's computer as on any server, never in the host's own browser (OQ-2.2-12) | F-45, doc 22 §13, 1.1 R10 |

### 5.2 Visual-readiness detector (`awaitReady`)

**Decided core (F-11, doc 22 §7):** ready when **all** hold at the same time: network idle ≥ 500 ms, `document.fonts` ready, no layout shift for 1 s; hard cap 15 s measured from the start of the `ready` step. S1/S2 replace network idle by "DOM mutation quiet for 1 s" and keep fonts ready. Thresholds are `[Estimate]`, tuned in the 20-site spike (F-11). The detector replaces any blind "wait N seconds" (MB§31).

| Signal | Measured by | Gating? |
|---|---|---|
| `network_idle` | In-flight count of HTTP(S) requests from Playwright events, zero for ≥ 500 ms; WebSocket, EventSource and media range requests excluded (OQ-2.2-16) | S0 only |
| `dom_quiet` | `MutationObserver` on the document subtree (`childList`, `characterData`, attributes except `style`), no mutation outside `ignore_selectors` for 1 s | S1, S2 |
| `fonts_ready` | `document.fonts.ready` resolved and no face with status `loading`; failed faces listed | all |
| `layout_stable` | No `layout-shift` entries and unchanged `scrollHeight` for 1 s (probe installed before navigation) | S0 |
| `wait_for_selector` | Recipe selector present and visible, counted inside the 15 s cap | if recipe |
| Recorded, not gating | Images in viewport decoded vs pending; lazy-pending count; running animations (`getAnimations()`); main-thread long tasks | no (feeds gate checks 6, 7, 9 in 2.10) |

`ReadinessReport` (P): `{mode, ready, capped, elapsed_ms, unmet_at_cap[], in_flight_hosts_at_cap[] (up to 5 hosts, no URLs), fonts{total, loaded, failed[]}, images{in_viewport, decoded}, animations_running}`. It is written into the manifest and the log. `awaitReady` is called again after 2.3's scroll pass (lazy loads), with `min(15 s, remaining step budget)`; a cap hit there is handled by the same per-rung rule as the first. **Field observation:** doc 08 treats the "scroll in ≈ 400 px steps, ≈ 200 ms waits, back to top, wait ≈ 3 s" sequence as a fallback under the detector, not a replacement; its parameters are 2.3's.

| Output per unit | ≈ 20–40 MB at DPR 2/3 | [Estimate] 1.3 §7.1 |

### Reliability

- No attempt can outlive its 90 s plus 60 s lease window even if the child ignores `abort` (1.4 R6, DC-03). The child adds a second line of defence (R4, exit 13).
- Losing the child loses at most one attempt (DC-03). It holds no durable state, so nothing needs reconciling (R2, R3).
- Closing a context in `finally` and recycling after abnormal attempts keeps one bad page from poisoning the next (R1, R24).
- Runtime changes (Playwright/Chromium pin, any 2.2 path) need the torture suite and canary before they ship (DC-12, 1.1 R11).

### Security and privacy

- Crawled pages are untrusted code (doc 15 #9): the child runs in a non-root container with restricted egress, no host mounts (the per-batch volume is a Docker volume, OQ-2.2-3), no credentials (R2, F-20). On the founder's computer the same container boundary applies (F-45): a page must not be able to reach the host or the local database.
- Everything the child records is a public page's content; it still keeps cookies, auth headers and request bodies out of evidence (R19) and keeps secrets out of logs (F-19 spirit).
- No stealth, no evasion (R10, R13). No `storageState` input exists in V0 (F-17); the field is a V2 hook.

### Cost recording

2.2 records no `CostEvent`. It reports per-step timings and byte counts so 2.9 can record browser time through 1.6 (1.4 §7).

### Observability (data for 1.8)

Per attempt: step timings; readiness elapsed and `capped`; `unmet_at_cap`; bytes and request counts (total, to the source domain, navigations); flags; overlays dismissed; module statuses; exit code of the child. Every stderr line carries `run_id, job_id, unit_id, attempt, strategy, step` (1.4 `logContext`). Useful derived metrics: readiness-cap rate per rung, dismisser hit rate, blocked rate (DC-18), S0 → S1 rescue rate.

## 8. Open Questions & Assumptions

### Open questions

Each entry: question — why it matters — **suggested default (a suggestion, not a decision).**

- **OPEN QUESTION OQ-2.2-1:** What does "1 request/s per domain" (F-10) count? (asked by review-wave-1 §4 and OQ-1.4-19) — A page load makes dozens of requests; counting them all makes one page take about a minute, counting only navigations leaves the in-page load unbounded. — **Suggested default:** it counts **top-level navigations and discovery/S3 fetches to the source's registrable domain**; subresources of a page that is already loading are not paced. 2.2 records `requests_total`, `requests_source_domain` and navigation times per attempt so the spike can measure the real rate; revisit with a cap on parallel same-domain subresource requests only if measurements show harm. Per-domain concurrency of 2 children already bounds the rest.
- **OPEN QUESTION OQ-2.2-2:** Child ↔ supervisor transport and framing. — DC-03 needs a heartbeat channel from a container with no database or Redis access. — **Suggested default:** newline-delimited JSON, commands on stdin, events on stdout, logs on stderr, files in the batch volume. Alternatives: a Unix socket in the volume. Decide with 2.9 and OQ-1.1-12.
- **OPEN QUESTION OQ-2.2-3:** Is it right that the child never uploads, and that the supervisor uploads the files and commits through one `withLease` (1.1 OQ-1.1-13 suggestion), with 2.2 supplying `buildAttemptInput` and `interpretAttemptResult`? Also: F-20/1.1 R15 say "no host mounts" while OQ-1.1-13 uses a per-batch volume. — The child cannot call `putBlob` or `getActiveRecipe` without credentials; the volume rule must not contradict F-20. — **Suggested default:** yes to both; the volume is a Docker named volume or tmpfs, not a host path mount; 2.9 deletes each attempt folder after commit or spool.
- **OPEN QUESTION OQ-2.2-4:** Does 2.9 or 2.2 own the module that starts the browser container (OQ-1.1-12)? — The launch mechanism touches the Docker socket (near-root). — **Suggested default:** 2.9 owns launching; 2.2 owns only what runs inside.
- **OPEN QUESTION OQ-2.2-5:** How is the 90 s attempt deadline divided? It starts at `startAttempt`, includes the supervisor's upload step (cap 30 s), and the step caps add up to 105 s. — DC-01 needs one binding total and the child needs a reserve for writing the manifest. — **Suggested default:** child total budget = remaining attempt time − 30 s upload reserve, i.e. about 60 s (`LIMIT_CHILD_TOTAL_S`); modules stop starting new sub-steps at 85% of it and return `partial` (2.3 flags `truncated`); a few hundred ms are reserved for the manifest.
- **OPEN QUESTION OQ-2.2-6:** `capture_step` is coarser than doc 22's sub-deadlines (scroll pass, section capture, media extraction). Which enum-level caps does 2.9 enforce for `capture` and `extract`? — Without numbers 2.9 cannot kill a hung step. — **Suggested default:** `navigate` 30 s, `ready` 15 s, `capture` 40 s (scroll 20 + sections 20), `extract` 20 s; `substep` text in heartbeats for logs only; steps never go backwards (R12 keeps extraction after `exitStatic`).
- **OPEN QUESTION OQ-2.2-7:** Where is `paceDomain` applied relative to the 90 s clock? 1.4 says "2.9 before navigation". — A pacing wait inside the attempt eats its budget; two navigations per unit (OQ-2.2-14 alternative) would need a second wait. — **Suggested default:** 2.9 calls `paceDomain` and waits after `leaseNextUnit` and before `startAttempt`; the child makes one navigation, so no second call is needed.
- **OPEN QUESTION OQ-2.2-8:** Values of locale, timezone, `Accept-Language` and colour scheme, and are they acceptable under DC-08/SC-03 ("no fingerprint spoofing")? — WF§9 says set them; the docs give no values. — **Suggested default:** `en-US`, `UTC`, `en-US,en;q=0.9`, `light`, identical for every site, recorded in `CaptureContext`, never varied to defeat a block. Founder to confirm they count as declared capture context, not spoofing. Geo- and personalization-dependent content is recorded, not eliminated (doc 23 #10).
- **OPEN QUESTION OQ-2.2-9:** Freeze time and seed randomness (WF§9 "freeze time")? — Freezing `Date` or timers stalls JS-driven motion in the motion pass and can hang sites. — **Suggested default:** not in V0. The static pass uses reduced motion + the freeze style; counters are handled by 2.3's frame selection ([Field observation] counter settled by choosing a frame). Revisit if the canary shows time-dependent noise.
- **OPEN QUESTION OQ-2.2-10** (wave-2 review: the owner is settled, 1.1's `CRAWLER_USER_AGENT` with content per F-10; only the exact string and mobile emulation stay open)**:** Honest user-agent content for both profiles, and `isMobile`/`hasTouch` emulation. — UA content is deferred between 1.1 and 1.5 (each points at the other); a UA with no `Chrome/` token can trigger "unsupported browser" pages, and a mobile layout may need touch and mobile viewport semantics. — **Suggested default:** owner 1.5/1.1 writes one string that names us, our contact URL and the real Chromium version; both profiles use it, the mobile profile adds only the standard `Mobile` token; `isMobile: true` and `hasTouch: true` for `mobile` as part of F-12 device emulation. Founder confirms this is not impersonation.
- **OQ-2.2-11 — resolved in the wave-2 review:** 1.4's `Lease.deviceProfile` now carries `code`, `viewport_width`, `viewport_height`, `device_scale_factor`. Original question kept for the record: How does the child learn the device profile? 1.4's `Lease` carries only `viewportProfile` (the `device_profile.code`), not the dimensions or DPR. — The child must never hard-code DPR (DC-20). — **Suggested default:** `buildAttemptInput` reads the `device_profile` row by code and passes it in `AttemptInput.profile`; 1.4 need not change.
- **OPEN QUESTION OQ-2.2-12:** Fonts, rendering backend and OS differences between the pinned image and the founder's computer (F-45). — Determinism, the golden-set baselines and gate check 7 depend on identical fonts and rasterization; a laptop may be macOS or Windows, with a GPU, a different screen DPR, other system fonts and less RAM than 2–3 slots × 2.5 GB. — **Suggested default:** capture only inside the pinned Linux `worker` image on the laptop too (R25); install a fixed, versioned font set in the image and record `fonts_image_version`, `host_os` and `image_digest` in `CaptureContext`; the host's display DPR and fonts never reach the page (viewport and DPR are explicit); the canary is run on the founder's machine and baselines are per image digest; slot count is a measured setting. Docker Desktop's Linux VM has no GPU, so WebGL runs on a software rasterizer (OQ-2.2-13).
- **OPEN QUESTION OQ-2.2-13:** Chromium launch flags and rendering backend: headless mode, software GL for WebGL canvases (the Stripe ribbon is one), `/dev/shm` size, Chromium sandbox vs `--no-sandbox` inside a container that already sandboxes (1.7). — Wrong choices give blank canvases, crashes, or a weaker sandbox. — **Suggested default:** decide in the spike; start with the new headless mode, software GL enabled, a larger `/dev/shm`, Chromium's own sandbox kept if 1.7's seccomp profile allows it, otherwise `--no-sandbox` accepted only because of the container sandbox. No flag may alter identity (R10).
- **OPEN QUESTION OQ-2.2-14:** Pass design and rung inheritance. (a) One navigation with the motion pass first and an in-place switch to static (reduced motion emulation + freeze style, reversible by `exitStatic`), versus a second navigation with reduced motion from context creation. (b) Does S1 produce only a static pass, and do S2/S3 inherit S1's environment? — A second navigation costs time and a second paced request; an in-place switch is less faithful for sites that read reduced motion at load; reversibility of the freeze is unverified; S1's freeze CSS makes a clean motion pass impossible. — **Suggested default:** (a) one navigation, in-place switch; fall back to two navigations only if the canary shows counters/reveals still wrong; (b) S1 static only with flag `static_only` (2.10 must not penalise a missing motion pass in S1), S2 inherits S1, S3 has no page. Confirm with 2.3 and 2.10.
- **OPEN QUESTION OQ-2.2-15:** Readiness cap per rung. Doc 22 §2 #1 says a cap hit escalates S0 → S1; F-11 alone could be read as "stop waiting and capture". — It decides whether slow pages burn a backoff before being captured. — **Suggested default:** S0 and S1 fail with `READINESS_CAP` (S1 by the DC-05 pattern, an inference), S2 proceeds with `readiness_capped`, as in §4.5.
- **OPEN QUESTION OQ-2.2-16:** Exact definition of "network idle" and "layout stable". — Autoplay video, WebSockets and analytics beacons otherwise keep many sites from ever being idle. — **Suggested default:** in-flight HTTP(S) requests excluding WebSocket, EventSource and media range requests; layout stable = no layout-shift entry and unchanged `scrollHeight` for 1 s; attribute mutations on `style` ignored for `dom_quiet`.
- **OPEN QUESTION OQ-2.2-17:** Block signals and non-200 pages. (a) Should the child use a 2.10-owned pure signature matcher (CAPTCHA frames, challenge titles) for early `blocked`, or only status codes? (b) For a 404/410 should it capture and let the gate reject, or fail fast? — (a) a challenge page served with 200 is only found by signatures; (b) capture-and-reject spends up to four attempts on a dead URL. — **Suggested default:** (a) status codes plus 2.10's matcher if it exports one, else status only; (b) capture and let the gate reject (doc 22 §2 #13 wants the fingerprint), and ask 2.10/1.4 whether 404/410 may end the ladder early.
- **OPEN QUESTION OQ-2.2-18:** Recipe and dismisser semantics. (a) Do recipe `cookie_dismiss_selectors` apply from S0 (a recipe that only works from S1 is useless)? (b) `ignore_selectors` meaning (1.5 leaves it open). (c) Dismisser policy: which control to prefer (reject/essential-only, then close, then accept), maximum clicks, whether to save a before-dismiss viewport shot as evidence, allowed vocabulary. — MB§60: never silently destroy evidence; clicks must not trip F-16 words. — **Suggested default:** (a) yes; (b) excluded from stability/overlay measurements and passed to 2.3, never hidden; (c) prefer reject/essential-only, then close, then accept only if nothing else exists; ≤ 3 clicks (`LIMIT_CONSENT_MAX_CLICKS`); `overlays` log always, before-shot only in S1+; a target whose accessible name matches F-16's deny keywords is never clicked.
- **OPEN QUESTION OQ-2.2-19:** Source of the tracker/analytics list. — SC-02's one-day bake-off decides between Scrapling's list and a public list; licence of lists is unverified. — **Suggested default:** until SC-02 reports, a small hand-maintained list of analytics, ad and session-replay domains kept in the repo; font and first-party hosts excluded (R20).
- **OPEN QUESTION OQ-2.2-20:** Resource bounds the child enforces (DC-01): redirects, main HTML bytes, total bytes per attempt, DOM nodes, open pages, consent clicks. — Nothing is decided, and "huge page" is a doc 08 edge case with a torture fixture. — **Suggested default** (placeholders for the spike): 10 redirects; main HTML 10 MB; 250 MB total per attempt; 200,000 DOM nodes; 3 pages open; 3 clicks.
- **OPEN QUESTION OQ-2.2-21:** Non-retryable outcomes. Off-domain redirect, non-HTML response and SSRF hits never succeed on a retry, but 1.4's ladder only ends early through `skipped`. — Four futile attempts per URL waste about 10 minutes of backoff. — **Suggested default:** report them as `skipped` with the reason codes `OFF_DOMAIN_REDIRECT`, `NON_HTML_RESPONSE`, `POLICY_DENIED`, as in §5.4; 1.4 confirms `skipped` may carry these codes and that the founder, not the system, adds a redirect target as a new site (F-46).
- **OPEN QUESTION OQ-2.2-22:** Diagnostic evidence on failed or blocked attempts. — The bad-page fingerprint library (gate check 3) grows from real challenge/error pages. — **Suggested default:** when a page exists, the child spends a reserved ≈ 5 s on one viewport screenshot and an HTML snapshot, added to the manifest as ordinary artifacts; skipped on crashes and aborts.
- **OPEN QUESTION OQ-2.2-23:** Where capture context lives (1.2 says browser/crawler version belong to `capture_session`/`capture_unit`; 1.4's tables have no such columns). — MB§40 and doc 04 want it on every capture. — **Suggested default:** write `capture-context.json` as a raw artifact (type `LOG`, `meta.role = capture_context`) per attempt, no column; 2.8 adds columns in V1. Alternative: 1.4 adds `capture_attempt.capture_context jsonb`.
- **OPEN QUESTION OQ-2.2-24:** Who collects and persists network metadata and console/page errors, and which headers are kept. — 2.4's network layer and doc 08 both need the same request log. — **Suggested default:** 2.2 owns the listeners and persists `NETWORK_METADATA` and `LOG` artifacts; 2.4 reads the in-process `NetworkLog`; headers kept by name allowlist (`content-type`, `content-length`, `cache-control`, `server`, `retry-after`, `location`, challenge-related names), never cookies/`Authorization`. Confirm with 2.3/2.4.
- **OPEN QUESTION OQ-2.2-25:** Chromium's maximum single-screenshot size at DPR 2/3 (a mobile page of 12,000 CSS px is 36,000 device px). — 2.3's tiling strategy and 1.3's blob cap depend on it. — **Suggested default:** measure on the pinned Chromium in the spike and publish the number as a constant 2.3 reads; 2.2 only sets DPR.
- **OPEN QUESTION OQ-2.2-26:** What 2.3 produces in S2 beyond viewport shots (section bounds without section images? DOM and accessibility only?), and whether a failed media module may leave the attempt `captured`. — Gate check 12 (section sanity) needs to know what to expect in `degraded` units. — **Suggested default:** S2 records section DOM bounds (cheap) but no per-section images; media failure never fails the attempt (A12). Confirm with 2.3, 2.4, 2.10.
- **OPEN QUESTION OQ-2.2-27:** Robots details. (a) Do robots rules apply to subresources of an allowed page? (b) Names and location of the pure robots matcher (2.1), the registrable-domain helper (1.1) and the SSRF guard (1.7) that the child imports. — "Honor robots always" (F-10) arguably includes resources, but blocking a disallowed `/static/` would produce broken renders; counsel input is due before the public library (F-18, E5). — **Suggested default:** (a) V0 matches top-level navigations only and records would-be-disallowed subresources; (b) each owner exports a pure function consumed by the child (no I/O, rules passed in).
- **OPEN QUESTION OQ-2.2-28:** Trusting an egress proxy CA in dev/CI sandboxes. — Needed for local work behind a proxy, but a blanket ignore-HTTPS-errors option would be unsafe. — **Suggested default:** a dev/CI-only setting that passes `--ignore-certificate-errors-spki-list=<hash>` for exactly one CA; never set in production; owner 1.1.
- **OPEN QUESTION OQ-2.2-29:** Standalone mode and the `capture try` CLI. — 2.11's fixtures and the 20-site spike need to run the child without Postgres or a supervisor. — **Suggested default:** adopt §4.8; the command only accepts a URL the founder types (F-46).
- **OPEN QUESTION OQ-2.2-30:** Crawler machine life cycle on the founder's computer (F-45). Sleep, battery, a closed lid and a home network behave differently from a server. — Docs such as OQ-1.1-14 (on-demand VM, idle shutdown) assumed a cloud VM. — **Suggested default:** nothing special in the child (E19: a lost attempt is retried); 2.9 and 1.1 decide how a crawl run keeps the machine awake and how pacing resumes after sleep.

### Assumptions

- **[Assumption] A1:** One attempt at a time per child; slots are children.
- **[Assumption] A2:** Consent banners reappear in every attempt because contexts are fresh (R1); the dismisser cost is accepted.
- **[Assumption] A3:** Navigation resolves on the main response and `DOMContentLoaded`; all later waiting is the detector's.
- **[Assumption] A4:** The child never compares wall-clock times with the database; budgets in `AttemptInput` are relative durations on its monotonic clock (1.4: DB clock for leases).
- **[Assumption] A5:** The child's identity-neutral emulation (viewport, DPR, mobile, locale) is not "fingerprint spoofing" under DC-08 (OQ-2.2-8, -10).
- **[Assumption] A6:** After an abnormal attempt the child asks to be recycled; 2.9 acts on it.
- **[Assumption] A7:** Service workers are blocked and downloads are refused for determinism and bounded disk use.
- **[Assumption] A8:** Hash-skip and re-crawl decisions happen before units are created (2.5, 3.4); 2.2 always performs the capture it is asked to and uses no conditional requests.
- **[Assumption] A9:** The same-registrable-domain compare uses a Public Suffix List library chosen by 1.1.
- **[Assumption] A10:** HTTP 401 on the main document maps to `AUTH_REQUIRED`.
- **[Assumption] A11:** Redirects to login-looking paths are recorded only; the gate decides.
- **[Assumption] A12:** A failed or timed-out media module does not fail the attempt (DC-10 spirit).
- **[Assumption] A13:** A top-level non-GET navigation caused by a V0 dismiss click is aborted; the V1 policy (2.6) will replace this.
- **[Assumption] A14:** Reusing one browser process for up to 50 attempts or 30 minutes with a fresh context each is safe (DC-07).
- **[Assumption] A15:** The founder's computer runs the same Docker-based Crawler VM role as a server would (F-45); the supervisor and child need no host-specific code beyond OQ-2.2-12 and OQ-2.2-30.
