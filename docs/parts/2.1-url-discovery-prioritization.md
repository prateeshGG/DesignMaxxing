**Labels:** `[Decision]` (with its ID) · `[Estimate]` · `[Assumption]` · `OPEN QUESTION OQ-2.1-n` · **(P)** = a name, value or rule this spec *proposes* because the source docs do not fix it. **Where things run (F-45, F-46).** Crawling runs on the founder's own computer, which takes the "Crawler VM" role everywhere (F-45). The site list is always chosen by a person (F-46): 2.1 never adds a site on its own, and only finds pages *inside* an approved site.

## 1. Purpose & Scope

**Purpose.** Turn "an approved site" into "the best ≤ 25 pages of that site, as capture units". 2.1 reads the founder's curated seed list into `source` rows, then, when 2.5 starts a site job, it checks robots.txt, finds candidate URLs cheaply (sitemap and HTML links, no browser), normalizes them to one canonical form, types and scores them, cuts to the crawl limits, and hands 1.4 the unit plan (page × device profile). It must never get a job stuck: every failure ends in a smaller plan or in `SKIPPED` units, never in silence (DC-04).

**Phase:** V0. Later-phase hooks are marked **[hook]** (F-40, template rule 3).

## 3. Data Model

Conventions follow 1.2: snake_case singular tables, `id uuid` UUIDv7 via `newId()`, `text` + `CHECK` enums, `ON DELETE RESTRICT`, `created_at`/`updated_at`, no soft delete. 2.1 owns three tables, all (P): `discovery_run`, `discovered_url`, `seed_import_row`. It owns no other table and writes other Parts' tables **only through their functions** (§3.4).

### 3.5 State machine: `discovery_run.state`

```
(no row) ──handler starts, claims row──► RUNNING ──persist plan (R-15)──► PLAN_COMMITTED ──createUnits ok──► UNITS_CREATED
                                           └──job closed / not open / source gone──► ABANDONED
```

`RUNNING → RUNNING` on re-delivery (a new handler run resumes; `handler_runs + 1`). `PLAN_COMMITTED` re-delivery skips straight to `createUnits`. `UNITS_CREATED` and `ABANDONED` are terminal.

## 5. Business Rules & Edge Cases

### 5.1 Rules

| # | Rule | Basis |
|---|---|---|
| R-1 | **No traffic without permission.** The handler calls `evaluateCollection` before the first request and again just before committing the plan. A deny ends discovery with a `SKIPPED` plan (§5.3) | 1.5 R-1, R-15; F-10; F-18 |
| R-2 | **Sites are person-chosen.** 2.1 never calls `createSource` from a discovered URL, sitemap entry, redirect target or link. Seed rows come only from a person-supplied CSV; admin additions go through 1.5/6.4. Links to other registrable domains are counted and dropped, never stored | F-46, DC-19 |
| R-3 | **Candidates get a homepage preview only; approved sites get full discovery.** Scope comes from `PolicyDecision.scope`: `homepage_only` for `candidate` (`seed_preview`), `full` for `approved`. `dropped` and takedown sources are never discovered | DC-19; 1.5 R-2, R-10 |
| R-4 | **Robots first, always.** robots.txt is the first request to a site. Its status is recorded with `recordRobotsFetch` before anything else is planned. Every later URL is matched against it. With `robots_override = true` (founder's logged override, 1.5), disallow rules are ignored but the file is still fetched and recorded; the override never changes any other limit | F-10; 1.5 R-3, R-4 |
| R-5 | **Robots skips are `SKIPPED`, never `BLOCKED`.** Site-level `disallow_all` (without override) produces `SKIPPED` units with `ROBOTS_DISALLOWED`, so they stay out of `BLOCKED %` | 1.5 R-4; DC-18 |
| R-6 | **One honest identity.** Every request uses the user-agent (with contact URL) from the effective policy. No other headers meant to look like a browser, no cookies kept between requests, no proxy, no TLS or fingerprint tricks. A 403/429/challenge response stops further requests to that site; it is recorded as the flag `http_blocked`, never worked around | F-10; DC-08; SC-03; SC-05; 1.5 R-5 |
| R-7 | **Paced and polite.** Every request, including robots, sitemaps and each redirect hop, first awaits `paceDomain`. Discovery requests run one at a time, so a site never sees more than 1 discovery request in flight (≤ 2 concurrent, F-10). `Crawl-delay` is honored through the effective interval (OQ-1.5-13) | F-10; DC-09; 1.4 §4.3 |
| R-8 | **SSRF check on every connection and redirect hop.** DNS is resolved by the guard and the connection goes to the checked address. The crawler machine is the founder's computer (F-45), so private, loopback, link-local and home-network ranges and cloud metadata addresses are all refused. A refused URL is excluded `SSRF_BLOCKED` and never fetched | F-20; F-45; 1.5 R-18 |
| R-9 | **One canonical form, one origin.** `canonicalizeUrl` rules (§5.2) apply to every URL. The crawl origin is the homepage's final scheme + host after same-registrable-domain redirects. `www.` and the bare domain are one site. A `/` that redirects within the origin to path P records P as `home_alias_path`; URLs equal to P merge into the homepage | F-25; DC-02; OQ-2.1-5, -6, -7 |
| R-10 | **Cross-domain redirect of the homepage = stop and tell the founder.** If the homepage's final registrable domain differs from `source.domain`, 2.1 plans `SKIPPED` homepage units, sets `redirect_target_domain` and the flag, and creates nothing for the target. The founder creates a source for the target and drops the old one (1.5 `status_reason`). A cross-domain redirect on any other URL excludes that URL (`REDIRECT_OFFSITE`) | OQ-1.5-24; F-46; DC-19 |
| R-11 | **Page type is a priority hint.** `discovered_url.page_type` is derived from URL, link prominence and (for fetched pages) title/H1. It is not the F-27 taxonomy label; 4.3 produces that as a `classification` row and may disagree | F-27; 1.2 OQ-1.2-16 |
| R-12 | **Score = page-type score.** `home` 100, `pricing` 90, `product` 85, `features` 80, `about` 60, `contact` 40, `blog` 20, `legal` 5 `[Decision F-10]`. Other types: OQ-2.1-2. A `trap_suspect` URL scores 0 and can be chosen only after all non-suspect candidates. Navigation prominence and content are tie-breakers only (OQ-2.1-3) | F-10; IF§7 |
| R-13 | **The cut.** Selected pages ≤ `target_pages` = min(`max_pages` ≤ 25, time-feasibility cap per OQ-2.1-14). Candidate order (deterministic): non-suspect first, score ↓, depth ↑, link prominence (nav, header, footer, body, sitemap), carried over from the previous planned run (OQ-2.1-4), shorter path, then canonical URL text. The homepage is always first when allowed. A per-family diversity cap applies (OQ-2.1-4). Same inputs always give the same plan | F-10; DC-13; DC-01 |
| R-14 | **Fail forward.** Whatever goes wrong on the site side (robots unreachable, sitemap broken, HTTP blocked, timeouts, budget exhausted, nothing found), the handler still ends with exactly one `createUnits(final=true)`: the best plan it has, or `SKIPPED` units. A job must never wait on discovery with no plan | DC-04; 1.4 §3.3 `units_planned_at` |
| R-15 | **Persist, then create; resume anywhere.** The handler claims `discovery_run` (UNIQUE per job), writes `discovered_url` rows as it goes, then commits the selection and `PLAN_COMMITTED` in one transaction, then calls `createUnits`, then sets `UNITS_CREATED`. On re-delivery, `PLAN_COMMITTED` skips straight to `createUnits` (all units come back `existing`, 1.4 `ON CONFLICT (unit_key)`); `UNITS_CREATED` is a no-op. Concurrent duplicate deliveries lose the claim and exit | F-24 idempotent consumers; DC-02; DC-14 |
| R-16 | **Everything is bounded.** Time, requests, page fetches, bytes, redirects, sitemap files, links per page, candidates, URL length, import rows (§4.4). Hitting a bound sets a flag and ends that sub-step; it never fails the job | DC-01 |
| R-17 | **No browser in V0 discovery.** 2.1 parses static HTML and sitemaps only. Pages whose links exist only after JavaScript are a known gap (doc 23 gap 12); behaviour is `low_discovery` plus a smaller plan (OQ-2.1-9) | [23](../23-scrapling-evaluation-and-collection-gap-analysis.md) gap 12; browser runtime is 2.2's |
| R-18 | **Seed import never overrides a person.** A CSV `founder_decision` is applied only when it is **new**: the domain has no `source` yet, or its decision differs from that domain's latest earlier import row. Takedown always wins (`conflict_takedown`). A `dropped` source returns to `approved` only when the CSV changed `drop` → `keep` (1.5 R-10). Existing rows with no earlier import row are changed only out of `candidate`; anything else is reported as `conflict_admin_decision` | DC-19; 1.5 R-8, R-10 |
| R-19 | **Competitor and unsafe seeds are refused per row.** `COMPETITOR_DOMAIN` (F-41), `SSRF_BLOCKED`, `UNSUPPORTED_SOURCE_TYPE` from `createSource` become row outcomes; the batch continues | F-41; 1.5 §4.1 |
| R-20 | **Policy limits are never raised.** `max_pages`, `max_depth`, `allowed_paths`, `blocked_paths`, `max_query_variants` and the pacing interval come from `getEffectivePolicy`, which is already clamped to F-10. `allowed_paths` non-empty restricts to matching paths; the homepage `/` stays eligible | F-10; 1.5 R-3 |
| R-21 | **Re-crawls rediscover.** Each crawl run runs discovery again (manual in V0, F-10): robots is refetched every run (OQ-1.5-15), candidates are re-found, and the previous planned run's selection is a tie-break (OQ-2.1-4) | F-10; 1.5 R-17 |
| R-22 | **Evidence of what robots said.** Each fetched robots body (2xx) is stored once per distinct content as a source-level `raw_artifact`; `recordRobotsFetch` carries the artifact id. Registration is guarded by 2.1's own check on `discovery_run.robots_artifact_id`, so re-delivery adds no second row (OQ-2.1-13) | F-10 "logged"; 1.3 §3.3; OQ-1.5-15 |
| R-23 | **Discovery never marks a site blocked or broken.** It records flags. Only unit outcomes (2.2/2.10) feed `BLOCKED %`, breakers and access status | DC-18; 1.5 R-12 |
| R-24 | **Verify before spending units** (default per OQ-2.1-10). Selected URLs that were not themselves fetched get one status-only request, within the request budget. 404/410 and login redirects are replaced by the next candidate | doc 22 #13; F-17; DC-01 |
| R-25 | **Logged-out only.** URLs that need authentication are not planned (`AUTH_REQUIRED`). A login or signup *page* is an ordinary public page and is typed `login` / `signup` | F-17 |
| R-26 | **Takedown wins during discovery.** The second `evaluateCollection` (R-1) catches a takedown or dropped status; the plan becomes `SKIPPED` units (`POLICY_DENIED`, `TAKEDOWN` if 1.4's code is used), with flag `policy_changed_during_run`. If `createUnits` refuses because 2.5 already closed the job, the run becomes `ABANDONED` | F-18; 1.5 R-7, R-15 |

### 5.2 Normalization, classification and scoring details (all (P); parameters in OQ-2.1-5, -11)

| Step | Rule |
|---|---|
| Parse | WHATWG URL parsing; resolve relative links against `<base href>` or the page URL; only `http`/`https` (else `UNSUPPORTED_SCHEME`); `mailto:`, `tel:`, `javascript:`, `data:` are dropped uncounted; length > `LIMIT_DISCOVERY_MAX_URL_LENGTH` → `URL_TOO_LONG` |
| Host | Lowercase, IDNA to punycode, strip trailing dot, default port and userinfo. `www.<domain>` and `<domain>` map to the origin host. Any other host → `OFFSITE_SUBDOMAIN` (same registrable domain) or dropped and counted (other domain). Scheme = the origin's scheme |
| Path | Resolve `.` / `..`; collapse repeated `/`; normalize percent-encoding (uppercase hex, decode unreserved); remove a trailing `/` except the root; `/index.html`, `/index.php` → `/` |
| Query | Remove tracking keys and session keys (lists: OQ-2.1-5). Sort remaining pairs by key, then value. URLs carrying secret-like keys (`token`, `key`, `secret`, `password`, `auth`, `email`, …) are excluded `SENSITIVE_URL` (F-19) |
| Fragment | Dropped, unless it is a hash route (`#/…`, `#!/…`), which stays |
| Hints | `<link rel=canonical>` on a **fetched** page that points to another same-origin URL: record the flag `canonical_hint_differs` and merge the two rows (`MERGED_DUPLICATE`). Unfetched candidates keep their normalized URL |
| Fetched page redirects | For URLs 2.1 requested, the canonical URL becomes the canonicalized final URL if same-origin; duplicates merge |

**Classification signal order (OQ-2.1-3):** (1) path patterns, (2) anchor text in `nav`/`header` for URLs the path leaves as `other`, (3) `<title>`/first `<h1>` of fetched pages. Default path patterns (P):

| Type | Path segments matched (first segment, case-insensitive) |
|---|---|
| `home` | `/` and `home_alias_path` |
| `pricing` | `pricing`, `plans`, `price` |
| `product` | `product`, `products`, `platform` |
| `features` | `features`, `feature`, `capabilities` |
| `about` | `about`, `company`, `team`, `careers`, `story` |
| `contact` | `contact`, `sales`, `support` |
| `blog` | `blog`, `news`, `articles`, `resources`, `changelog`, `stories` |
| `legal` | `privacy`, `terms`, `legal`, `cookies`, `cookie-policy`, `security` |
| `docs` | `docs`, `documentation`, `developers`, `api`, `guides`, `help` |
| `login` | `login`, `log-in`, `signin`, `sign-in` |
| `signup` | `signup`, `sign-up`, `register`, `get-started`, `trial` |
| `other` | everything else (`customers`, `solutions`, `integrations`, …) |

**Trap suspects (OQ-2.1-11)** get the flag `trap_suspect`: date-path calendars, sort/filter/facet/pagination (`page` ≥ 2) and search-result query keys, `/tag/`, `/category/`, `/author/`, `/archive`, feed and `wp-json` paths. At most `max_query_variants` (1.5; suggested 3) distinct queries are kept per path; the rest are excluded `QUERY_VARIANT_CAP`.

### 5.3 The handler, step by step

| Step | Action | On problem |
|---|---|---|
| 0 | Re-read job and source; claim `discovery_run` (insert or resume). Job not `RUNNING`/`QUEUED`, or source missing → `ABANDONED`. `UNITS_CREATED` → return; `PLAN_COMMITTED` → jump to step 10 | |
| 1 | `evaluateCollection` with the purpose (OQ-2.1-17). Deny → plan = `SKIPPED` homepage units, reason `POLICY_DENIED` (or `ROBOTS_DISALLOWED` for `robots_disallow_all`); go to 9 | R-1 |
| 2 | Compute budget: time = min(`LIMIT_DISCOVERY_MAX_SECONDS`, 25% of `deadline_at − now` `[Assumption]`); requests = `LIMIT_DISCOVERY_MAX_REQUESTS`. Read `getEffectivePolicy` | |
| 3 | Fetch robots.txt (≤ 1 immediate retry on 5xx/timeout). Parse. `recordRobotsFetch` (status `fetched` / `disallow_all` / `not_found` / `unreachable`). `disallow_all` without override, or `unreachable` (OQ-2.1-12) → `SKIPPED` plan, go to 9 | R-4, R-5 |
| 4 | Fetch the homepage (`origin/`), following redirects (≤ 5, each hop checked and paced). Cross-domain → R-10 plan, go to 9. Set `origin_url`, `home_alias_path`. Seed preview (`scope = homepage_only`): plan the homepage only, go to 9 | R-9, R-10 |
| 5 | Sitemaps: robots `Sitemap:` URLs first, else `/sitemap.xml`; follow indexes ≤ 2 levels, ≤ file/byte limits; entries on other hosts are ignored; XML parsed with DTD and external entities disabled; gzip size-capped | R-16 |
| 6 | Links: parse homepage HTML, then fetch the best-scoring unfetched candidate with depth < `max_depth`, repeatedly (best-first), until the page-fetch, request or time budget ends or none is left | OQ-2.1-9 |
| 7 | Normalize, classify, score, apply filters (robots per URL, `allowed_paths`/`blocked_paths`, depth, scope, non-HTML by extension and `Content-Type`, traps, sensitive, locale alternates). Write `discovered_url` rows | |
| 8 | Order and cut (R-13) to `target_pages`; verification pass (R-24); replace failures with the next candidates | |
| 9 | Re-run `evaluateCollection` (R-26). Build units: for each selected page, one unit per profile (OQ-2.1-18, -21) with `priority = score`. Commit selection + `PLAN_COMMITTED` + `outcome` in one transaction | |
| 10 | `createUnits({ …, final: true })` in one call (≤ 50 units + skipped). Set `UNITS_CREATED` | job closed → `ABANDONED` |

Time-feasibility cap `[Estimate]` (OQ-2.1-14): `pages_feasible = floor(0.8 × (deadline_at − now) ÷ (profiles × max(40 s ÷ 2, interval_s)))`. With the defaults (2 profiles, 1 s interval, about 100 s used by discovery) this is 34, so the 25-page limit binds. With `Crawl-delay: 30` it is 22.

| Area | Note |
|---|---|
| Capacity `[Estimate]` | ≈ 500 sites (F-07); ≤ 40 requests per site job ≈ 20 000 requests per full run. At 1 request/s per site and ≈ 3 min per site, sites run in parallel across domains (per-domain pacing, DC-09); consumer concurrency is OQ-2.1-8. `discovered_url` ≤ 500 rows per site, ≈ 250 000 rows per full run: trivial for Postgres. Seed import: 94 candidate rows today (`seeds/candidates-v0.csv`), cap 1000 |

| Reliability | Postgres holds all discovery state (DC-14); losing Redis loses nothing (E-31). The handler is resumable at three points (R-15). No lease is needed because discovery has no zombie risk: writes are idempotent claims |
| Where it runs | The crawler machine, which is the founder's computer (F-45): it may sleep or be offline (E-32); its home network is exposed to anything the site links to, so the SSRF guard (R-8) is a hard requirement here; traffic comes from the founder's own IP address, which is another reason for polite pacing and no evasion (R-6, DC-08) |

| Cost | No `CostEvent` in V0: discovery is cheap non-browser HTTP; browser time is the cost driver (doc 13). Counts are logged and in `counts` (OQ-2.1-26) |
| Observability (data for 1.8) | Discovery duration; requests per site; candidates, selected pages and units per site; outcome mix (`planned`, `planned_homepage_only`, `skipped_*`, `abandoned`); counts of each flag (`low_discovery`, `http_blocked`, `cross_domain_redirect`, `no_sitemap`); robots status mix; runs `RUNNING` older than the handler timeout; seed import outcome counts. Logs carry `run_id`, `job_id`, `source_id`, `stage` (a 2.1 addition to 1.4's `logContext`, which has unit fields 2.1 does not have) |
| Determinism | Same fetched inputs and policy always give a byte-identical plan (R-13). The discovery run stores its inputs (`limits`) so a plan can be explained |

## 8. Open Questions & Assumptions

### Open questions

Each entry: the question — why it matters — **Suggested default (a suggestion, not a decision).**

- **OPEN QUESTION OQ-2.1-1:** Confirm every (P) name: tables `discovery_run`, `discovered_url`, `seed_import_row`; enum values; function names; CLI commands; `LIMIT_DISCOVERY_*` keys; module location `services/web-crawler/discovery/`; and that 2.1 adds no BullMQ job or queue beyond the 1.4 `ev.discovery` consumer. — 2.5, 2.2, 3.2 and 6.4 code against them; `web-crawler` is shared with 2.2. — **Suggested default:** accept as written; rename only for consistency with later waves.
- **OPEN QUESTION OQ-2.1-2:** The two page-type lists differ: F-10 has `legal`, F-27 has `docs`, `login`, `signup`; scores exist only for F-10's eight types. What vocabulary does 2.1 use, and what do the other types score? — F-10 scores drive the cut; F-27 is the taxonomy 4.3 will label with (review-wave-1 §4; OQ-1.2-16). — **Suggested default:** use the union (`home, pricing, product, features, about, contact, blog, legal, docs, login, signup`) plus `other`; F-10 scores unchanged; placeholder scores `other` 30, `docs` 20, `signup` 10, `login` 10, tuned on the 20-site spike. 4.3 stays free to use the F-27 list; 2.1's list is only a hint (R-11).
- **OPEN QUESTION OQ-2.1-3:** IF§7 scores "URL semantics + navigation prominence + page content", but F-10 gives only page-type scores. How do prominence and content enter? — Without a rule, ordering inside one type is arbitrary. — **Suggested default:** the page-type score alone is the unit priority; prominence (nav > header > footer > body > sitemap) and fetched-page title/H1 are tie-breakers and a fallback signal for `other`; the signal order and the path table in §5.2 are the V0 rule.
- **OPEN QUESTION OQ-2.1-4:** Diversity and stability of the cut. A site with 40 `/product/…` or `/blog/…` pages could fill all 25 slots with one family, and a re-crawl could pick a different 25. — Library value needs variety; version continuity (3.4) needs stable pages. — **Suggested default:** at most 3 URLs per first-path-segment family, except `home`, `pricing`, `product`, `features`, `about`, `contact`, which are exempt; ties broken in favour of URLs selected in the previous planned run of the same source; no score bonus.
- **OPEN QUESTION OQ-2.1-5:** The normalization rule set (§5.2): trailing-slash removal, index-file removal, hash-route handling, `www.` unification, tracking/session/secret key lists, canonical hints, length cap. — The canonical URL is page identity (F-25) and unit identity (DC-02); a wrong rule merges or splits pages permanently. — **Suggested default:** the §5.2 rules. Tracking keys: `utm_*`, `gclid`, `gbraid`, `wbraid`, `dclid`, `fbclid`, `msclkid`, `yclid`, `twclid`, `ttclid`, `li_fat_id`, `igshid`, `mc_cid`, `mc_eid`, `_hsenc`, `_hsmi`, `hsa_*`, `mkt_tok`, `_ga`, `_gl`. Session keys: `sid`, `sessionid`, `phpsessid`, `jsessionid`, `aspsessionid`. Secret-like keys: `token`, `access_token`, `key`, `api_key`, `apikey`, `secret`, `password`, `auth`, `code`, `sig`, `signature`, `email`. Ambiguous keys (`ref`, `source`) are kept.
- **OPEN QUESTION OQ-2.1-6:** Scope of "the site": other subdomains (`docs.`, `blog.`, `app.`), and locale copies. — 1.5 defines one source per registrable domain; subdomains can be real marketing pages or login apps; locale copies can flood the cut. — **Suggested default:** the origin host plus its `www.` alias only; other subdomains excluded and flagged (`subdomains_seen`); keep the homepage's locale (path prefix like `/en/` or `<html lang>`), exclude other locale prefixes and hreflang alternates.
- **OPEN QUESTION OQ-2.1-7:** What is "depth" (F-10, ≤ 3) for URLs found only in a sitemap, and how does the homepage alias work? — Sitemap URLs have no link path; without a rule the limit is bypassed or unusable. — **Suggested default:** link-found URLs use link distance from the homepage (home = 0); sitemap-only URLs use their path-segment count (`/pricing` = 1, `/blog/post` = 2); depth > 3 is excluded `DEPTH_EXCEEDED`.
- **OPEN QUESTION OQ-2.1-8:** Discovery budgets, HTTP client defaults and consumer concurrency (§4.4): time, requests, fetches, bytes, redirects, timeout, links, candidates, the 25%-of-remaining-time clamp, `Accept-Language`, and how many discoveries run at once. — DC-01 requires every bound; discovery eats into the 30-min job (DC-13); a locale header should match 2.2's capture locale. — **Suggested default:** the §4.4 values; the clamp as in step 2; `Accept-Language` the same as 2.2's capture locale; discovery consumer concurrency 4 `[Estimate]`; no cookies, GET only.
- **OPEN QUESTION OQ-2.1-9:** Link discovery strategy and the JavaScript-site gap. — Doc 23 gap 12: HTTP-only discovery misses routes of SPAs; browser-observed links are a listed source (doc 03) but the browser is 2.2's. — **Suggested default:** best-first static link expansion from the homepage (§5.3 step 6); flag `low_discovery` when fewer than 5 candidates besides the homepage are found; no browser-based discovery in V0; decide after the spike whether 2.2/2.3 should return rendered homepage links for 2.1 to use.
- **OPEN QUESTION OQ-2.1-10:** Verify selected URLs with a status-only request before creating units? — Planning a 404 or login-gated page costs up to 4 attempts × 2 viewports before quarantine (doc 22 #13). — **Suggested default:** yes, bounded by `LIMIT_DISCOVERY_MAX_VERIFY` and the request budget; HEAD, falling back to a headers-only GET; failures replaced by the next candidate; if the budget is exhausted, flag `verification_skipped` and plan unverified.
- **OPEN QUESTION OQ-2.1-11:** The trap heuristics list and treatment (§5.2), the value of `max_query_variants` (OQ-1.5-12), and the glob dialect for `allowed_paths`/`blocked_paths` (a 1.5 field also edited in 6.4). — IF§6 says "deprioritize", not "exclude"; one dialect must serve 1.5, 2.1 and 6.4. — **Suggested default:** the §5.2 list, deprioritize (score 0, chosen last) except the variant cap, which excludes; `max_query_variants` = 3 per path; dialect: `*` matches within one path segment, `**` across segments, matched against the normalized path (owner: 1.5 confirms).
- **OPEN QUESTION OQ-2.1-12:** Final robots policy (OQ-1.5-14 leaves the final call to 2.1): missing file, unreachable file, redirects, HTML served as robots, retry, and the product token used for group matching. — A wrong default either crawls unpermitted paths or skips sites on a blip. — **Suggested default:** RFC 9309. 4xx → `not_found`, no restrictions. 5xx/timeout after one immediate retry → `unreachable`, `SKIPPED` units (reason `POLICY_DENIED`, deny reason `robots_unavailable`), retried by the next run. Follow ≤ 5 redirects within the registrable domain; a cross-domain redirect or longer chain → `unreachable`. 200 with no valid directives → no restrictions. The product token is the first token of the configured user-agent string (value owned by 1.1/1.5).
- **OPEN QUESTION OQ-2.1-13** (wave-2 review: 1.3 now proposes `raw_artifact_type` values `ROBOTS_TXT` and `SITEMAP` and a partial unique index for source-level evidence; use those instead of `HTML` if the founder accepts)**:** How robots.txt (and, optionally, sitemaps) are stored as evidence. — 1.3's `raw_artifact_type` has no robots type; OQ-1.3-5 does not map it; the registry's unique index `(capture_attempt_id, type, sha256)` does not dedupe rows whose `capture_attempt_id` is null (NULLs are distinct in Postgres). Owner: 1.3. — **Suggested default:** type `HTML` (its lifecycle is a cold move, not deletion) with MIME `text/plain` and `meta.document_kind = 'robots_txt'`; store the robots body only for 2xx responses; do not store sitemaps in V0; 2.1 guards against duplicate rows itself (R-22) and asks 1.3 to add a partial unique index for source-level rows.
- **OPEN QUESTION OQ-2.1-14:** The crawl-delay and time-feasibility cap (OQ-1.5-13: "the site gets fewer pages, 2.1 prioritizes"). — A long `Crawl-delay` must reduce pages rather than guarantee a missed 30-min deadline. — **Suggested default:** the §5.3 formula `pages_feasible = floor(0.8 × (deadline_at − now) ÷ (profiles × max(40 s ÷ 2, interval_s)))`, using doc 22's `[Estimate]` of 40 s per unit and 2 concurrent; flag `time_feasibility_cap` when it binds; the 0.8 safety factor is a placeholder for the spike.
- **OPEN QUESTION OQ-2.1-15:** Cross-domain redirects (OQ-1.5-24): is the §R-10 response right, and where does the founder learn about it? — Gate check 1 would reject every unit of such a site; no inbox category fits it (doc 22 §10 lists five). Needs a new reason code in 1.4's additive list (owner 1.4) and a display in 6.4. — **Suggested default:** `SKIPPED` units with reason code `OFF_DOMAIN_REDIRECT` (wave-2 review: renamed from `CROSS_DOMAIN_REDIRECT`; one name shared with 2.2's `OFF_DOMAIN_REDIRECT`, now in 1.4 §3.11 as (P)); the flag `cross_domain_redirect` and the outcome `skipped_cross_domain_redirect` keep their names (they are not unit reason codes); `redirect_target_domain` shown on the seed review and source page in 6.4 with a prefilled "add site"; counted in the daily summary (1.8); no inbox category in V0.
- **OPEN QUESTION OQ-2.1-16:** Planning outcomes and job roll-up (owner 2.5). — (a) 2.1 plans `SKIPPED` units when a whole site is denied (R-5, R-10), so the job can finish; how does 2.5's F-32 70% rule count a job with only `SKIPPED` units, and which denominator does it use (`units_planned.page_count`)? (b) If the discovery delivery dies after 3 attempts (E-33), nothing ends the job before its 30-min deadline. — A stuck-before-planning job is exactly the "RUNNING forever" failure (DC-04). — **Suggested default:** (a) `SKIPPED` units are excluded from the denominator and a job with no non-skipped unit rolls up as `COMPLETED` with `partial = false` and `status_reason` from the skip; (b) 2.5's janitor treats a `RUNNING` job with `units_planned_at` null and no live handler for 10 minutes as `FAILED` with `status_reason = DISCOVERY_FAILED`.
- **OPEN QUESTION OQ-2.1-17:** `capture_job.started` carries no `purpose` (seed preview, crawl, re-crawl), and 1.5's event table lists 2.1 as a possible consumer of `source.created` "to start a seed preview". — 2.1 needs the purpose for `evaluateCollection`; 2.5 owns starting work. - **OPEN QUESTION OQ-2.1-19:** Seed import semantics beyond R-18. — (a) `createSource` returns only `Source`, so the import cannot tell "created" from "already existed" (the HTTP route can); (b) 1.5 has no function to change `category`/`notes` of an existing source; (c) a `dropped` new row needs `status_reason`, which `createSource` does not take; (d) the first import of a file for sites that already exist. — The report and the founder's trust in it depend on these. — **Suggested default:** (a) 1.5 returns `{ source, created }`; (b) 1.5 adds `category` and `notes` to `updatePolicy` (differences are only reported in V0); (c) create as `candidate`, then `setSeedStatus(dropped, reason = "seed import <file> line <n>")`; (d) apply only `candidate` → `approved`/`dropped`; everything else is `conflict_admin_decision`.
