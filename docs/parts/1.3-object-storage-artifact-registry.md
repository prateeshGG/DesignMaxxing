## 1. Purpose & Scope

**Purpose.** Store every heavy file the collection system produces exactly once, by content hash, in Cloudflare R2. Keep a Postgres registry that says what each file is, where it came from and what it was derived from. Enforce that raw evidence is never modified. Guarantee that a crash, a storage outage or a full disk never loses committed evidence and never leaves a half-written record. Clean up files nobody references.

### 3.2 Key scheme (content-addressed)

[Decision] Keys are content-addressed by SHA-256 with a two-character fan-out (§44 `assets/ab/ab123…`). [Assumption] Per-source structure (the IF§20 per-website layout) is held in registry rows, not in keys (A-20, C-10). The class/type segment exists so that the F-33 lifecycle rules (by artifact type) can be expressed as R2 prefix rules later.

| Prefix pattern **(proposed)** | Holds | Example |
|---|---|---|
| `raw/<type>/<h0h1>/<sha256>` | Raw evidence. `<type>` = lower-case `raw_artifact.type` | `raw/screenshot/3f/3fa9…e1` |
| `der/<kind>/<h0h1>/<sha256>` | Derived artifacts. `<kind>` = `derived_artifact.kind` | `der/display_webp/07/07c2…9b` |
| `backups/…` | Reserved for 1.7 (`pg_dump`); layout owned by 1.7 | — |

Rules:

1. `<sha256>` = lower-case hex SHA-256 (64 chars) of the **exact bytes stored** (OQ-1.3-9 on compression). `<h0h1>` = its first two characters.
2. No file extension. The MIME type is stored in the registry and set as the object's `Content-Type`.
3. A key is written once and never overwritten with different bytes (true by construction: different bytes give a different key). Identical bytes give the same key, so they dedupe within a prefix: 20 sources that use one asset produce **1 blob and 20 registry rows** (§44).
4. Object metadata on PUT: `Content-Type = mime_type`, custom metadata `sha256`. `der/` objects also get `Cache-Control: public, max-age=31536000, immutable` because their keys never change content (for 6.1's delivery).
5. GC, integrity checks and lifecycle rules act only on `raw/` and `der/`. Any other prefix is ignored.

### 3.3 `raw_artifact` (owned)

Fields from §4/doc 12 are `[Decision]`; extra fields are **(proposed)** under OQ-1.3-4 / OQ-1.3-6.

| Column | Type | Constraints | Source / owner of the value |
|---|---|---|---|
| `id` | uuid | PK, UUIDv7 | [Decision] F-23; generated per 1.2 |
| `source_id` | uuid | NOT NULL, FK → `source.id` | §4; set by the capturing Part |
| `capture_attempt_id` | uuid | FK → `capture_attempt.id`; NOT NULL except for source-level evidence (robots.txt, sitemaps) registered by 2.1 | §4 `capture_id`, renamed in the wave-1 consistency review (OQ-1.3-4 resolved). **[V1 hook]** also null for `USER_UPLOAD` sources (F-22, doc 04 §39) |
| `type` | enum `raw_artifact_type` | NOT NULL | [Decision] §4 values below |
| `storage_key` | text | NOT NULL; CHECK `storage_key = 'raw/' \|\| lower(type::text) \|\| '/' \|\| substr(sha256,1,2) \|\| '/' \|\| sha256` | Computed by `storageKeyFor` |
| `sha256` | text | NOT NULL; CHECK `sha256 ~ '^[0-9a-f]{64}$'` | [Decision] §4, §44 |
| `mime_type` | text | NOT NULL | §4 |
| `size` | bigint | NOT NULL, > 0, ≤ type limit (§5 rule R10) | §4; bytes |
| `stored_at` | timestamptz | NULL = bytes only in the Crawler VM spool; set once when the blob is in R2 | **(proposed)** OQ-1.3-3 |
| `meta` | jsonb | NOT NULL DEFAULT `'{}'` | **(proposed)** OQ-1.3-6; keys owned by the producing Part. For `SCREENSHOT` the keys `width_px`, `height_px`, `dpr` are required (DC-20) |
| `created_at` | timestamptz | NOT NULL | §4; per 1.2 convention |

**Enum `raw_artifact_type`** [Decision §4]: `SCREENSHOT, VIDEO, HTML, DOM, UI_TREE, NETWORK_METADATA, ASSET, APP_PACKAGE, LOG, TRACE`. V0 uses all except `APP_PACKAGE` (**[V2 hook]**, mobile). (wave-2 review) **(P)** Two more values for source-level evidence (`capture_attempt_id` NULL): `ROBOTS_TXT` (robots.txt bodies, MIME `text/plain`, key prefix `raw/robots_txt/…`) and `SITEMAP` (sitemap files, if a Part chooses to keep them; 2.1 stores none in V0). They are additive enum values proposed here, not part of the [Decision] §4 list. 2.1's OQ-2.1-13 suggested type `HTML` with `meta.document_kind` instead; if the founder accepts this, `ROBOTS_TXT` replaces that suggestion. Mapping of the accessibility tree, computed styles, performance timings, console errors, section screenshots and downloaded media to these values: **OQ-1.3-5**.

**Indexes.** Unique `(capture_attempt_id, type, sha256)` (idempotent re-registration, R13). A second partial unique index `(source_id, type, sha256) WHERE capture_attempt_id IS NULL` does the same for source-level evidence such as robots.txt, because NULLs never collide in a normal unique index (added in the wave-2 review). B-tree `(storage_key)` (GC and integrity lookups). B-tree `(source_id)` (takedown). B-tree `(capture_attempt_id)`. Partial `(created_at) WHERE stored_at IS NULL` (flusher and lost-spool check).

**Immutability** [Decision §6, MB§40]. A trigger rejects every `UPDATE` except setting `stored_at` from NULL to a value. Rows are deleted only through §4.6 (takedown, lifecycle, admin) — never edited.

**Data class.** Every row is data class `raw_capture` (doc 04, GAP§1). Provenance fields are added by 1.6; 1.3 reserves no columns for them.

### 3.5 Registry completeness rule (touches other Parts)

Every blob under `raw/` or `der/` must be referenced by at least one `raw_artifact` or `derived_artifact` row once its 48 h grace period has passed. **Other tables never hold a `storage_key` that is not registered.** `Asset.storage_key` (doc 05, owned by 1.2/3.2) must equal the `storage_key` of a registered artifact. This is what makes orphan GC (doc 22 §9) safe with one lookup. Confirmation requested in OQ-1.3-6.

### 3.6 Local spool (Crawler VM only; not a table)

| Item | Value |
|---|---|
| Location | Directory from config `STORAGE_SPOOL_DIR` **(proposed)** on a Docker volume (1.1). Unset on the App VM = spooling disabled there |
| Layout | `<STORAGE_SPOOL_DIR>/<storage_key>` (same key as R2) plus `<…>.json` sidecar with `sha256`, `size`, `mime_type`, `spooled_at` |
| Write | Write to a temp name, `fsync`, rename (atomic). Sidecar written the same way |
| Manifest | None separate: rows with `stored_at IS NULL` are the manifest (OQ-1.3-3) |

(wave-2 review) **The spool also covers the internet being down.** Under F-45 the crawler machine is the founder's computer, which can lose its connection (Wi-Fi switch, VPN, a closed lid). Whenever R2 is in use and the machine cannot reach it, `putBlob` spools exactly as in an R2 outage (E2) and `flushSpool` uploads when the connection returns; the object-storage breaker (2.9) treats the two the same. If R2 is replaced by local disk before launch (§2), the spool is not needed for storage until R2 is switched on. Founder question: review-wave-2 §5 item 3; network path: 2.9 OQ-2.9-40.

### 3.7 State of a blob

```
           putBlob ok                                 (no row after 48 h)
 bytes ──────────────► IN_R2 ──── row committed ──► REFERENCED ──► (rows deleted) ──► UNREFERENCED ──► deleted by GC / delete fn
   │                     ▲
   │ upload fails /      │ flushSpool ok (sets stored_at)
   │ breaker open        │
   └──────────► IN_SPOOL ┘ ──── no row after 48 h ──► spool file deleted by spool GC
```

These states are derived from facts (object exists, row exists, `stored_at`), not stored as a column.

## 4. API Surface

[Decision] No HTTP endpoints and no `/internal/*` routes (F-24). Interfaces are TypeScript functions in `packages/storage` **(proposed module name**; doc 02 lists `packages/storage`; layout owned by 1.1), plus CLI subcommands. Every function that does I/O takes an `AbortSignal` (doc 22 §5 deadlines).

### 4.1 Keys

```ts
type BlobClass = 'raw' | 'der';
storageKeyFor(cls: BlobClass, typeOrKind: string, sha256: string): string   // pure; throws InvalidKeyInput
```

### 4.2 Upload

```ts
putBlob(input: {
  cls: BlobClass; typeOrKind: string; mimeType: string;
  body: Buffer | { filePath: string };
  signal: AbortSignal;                       // caller passes the 30 s upload sub-deadline (doc 22 §5)
}): Promise<{ storageKey: string; sha256: string; size: number; stored: boolean }>
```

| Behaviour | Detail |
|---|---|
| Hash | SHA-256 and size computed while reading the body |
| Size check | Rejects above the limit for the type (R10) with `ArtifactTooLarge` before any network call |
| Dedupe | `HEAD` the key; if it exists with the same size → no PUT, `stored: true` (§44) |
| Upload | Single `PUT` with `Content-Type`, `sha256` metadata and a provider checksum if supported (OQ-1.3-16); bounded retries inside `signal` |
| Breaker | If the object-storage breaker (2.9) is open, skip the upload attempt. (wave-2 review) **(P)** The breaker reaches `packages/storage` by dependency injection, never by import: the storage client is constructed with `deps.isOpen: () => boolean \| Promise<boolean>` (supplied by 2.9; the supervisor and `worker-app` wire it to `isGlobalBreakerOpen('object_storage')`) and optionally `deps.reportCall(outcome: { ok: boolean; reason?: string })` (wired to 2.9's `reportGlobalCall`). With no `isOpen` supplied (tests, the CLI) the breaker is treated as closed. A throwing `isOpen` counts as closed (2.9 R25: fail open on reading a global breaker) |
| Spool fallback | On final failure or open breaker: if `STORAGE_SPOOL_DIR` is set, write to spool and return `stored: false`; otherwise throw `StorageUnavailable` (retryable) |
| Spool full | If the disk is above the hard-stop watermark (90%, doc 22 §9) throw `SpoolFull` (retryable; the unit attempt fails and 1.4 retries it) |
| Idempotency | Safe to call any number of times with the same bytes |
| Auth | Uses the deployable's R2 credentials (§7.3) |

### 4.3 Register (inside the caller's transaction)

```ts
registerRawArtifact(tx, input: {
  sourceId; captureAttemptId: string | null; type: RawArtifactType;
  storageKey; sha256; mimeType; size; stored: boolean; meta?: object;
}): Promise<RawArtifact>          // stored=false → stored_at NULL

registerDerivedArtifact(tx, input: {
  rawArtifactIds: string[]; kind; producer; producerVersion; inputHash;
  storageKey; sha256; mimeType; size; meta?: object;
}): Promise<DerivedArtifact>

findDerivedArtifact(q: { kind; producer; producerVersion; inputHash }): Promise<DerivedArtifact | null>   // cache lookup (§43)
```

- **Write order** [Decision DC-02, doc 22 §4]: `putBlob` first, then `register*` in the caller's transaction. The caller (2.x) makes that transaction conditional on its `lease_id` (owned by 1.4), so a zombie worker's rows are never committed; its blob becomes an orphan and is GC'd.
- **Idempotency:** `registerRawArtifact` is `INSERT … ON CONFLICT (capture_attempt_id, type, sha256) DO NOTHING` and returns the existing row. `registerDerivedArtifact` likewise on `(kind, producer, producer_version, input_hash)`.
- **Validation errors** (`InvalidArtifact`): key does not match type/kind and hash; unknown `kind`; missing required `meta` keys; a `raw_artifact_ids` element that does not exist; a derived image wider than its source raw image (never upscale, DC-20; checked when the source has `width_px`).

### 4.4 Read

```ts
openArtifact(ref: { rawArtifactId } | { derivedArtifactId } | { storageKey },
             opts: { verify?: boolean /* default true */; signal }): Promise<Readable>
readArtifactBytes(ref, opts): Promise<Buffer>
signedReadUrl(storageKey: string, ttlSeconds: number /* ≤ 3600, proposed */): Promise<string>
listRawArtifacts(filter: { sourceId?; captureAttemptId?; type?; createdBefore?; createdAfter? }, page): Promise<Page<RawArtifact>>
```

| Behaviour | Detail |
|---|---|
| Resolution | On the Crawler VM: spool first, then R2. Elsewhere: R2 only; a row with `stored_at IS NULL` → `BlobNotYetStored` (retryable) |
| Verify | Recomputes SHA-256 while streaming; mismatch → `IntegrityError` (not retryable; alerts) |
| Missing | `ArtifactNotFound` (row missing) or `BlobMissing` (row exists, object missing; alerts) |
| Signed URL | Short-lived R2 presigned GET for admin viewing of evidence (6.4). Not for public delivery (6.1, OQ-1.3-1). Whether `web` holds R2 read credentials: OQ-1.3-20 |

### 4.5 Spool

```ts
flushSpool(opts: { signal; maxFiles?: number }): Promise<{ uploaded; remaining; failed; orphansDeleted }>
spoolStats(): Promise<{ files; bytes; oldestAgeSeconds }>
```

Flush per file: `PUT` (idempotent) → `UPDATE raw_artifact SET stored_at = now() WHERE storage_key = $1 AND stored_at IS NULL` → delete the spool file **only if** at least one row was updated or a row with `stored_at` set already exists. A spool file with no row and older than 48 h is deleted (spool orphan). Called every 60 s **(proposed)** by a loop on the Crawler VM (host process: OQ-1.3-18), by the disk guard at 80% (2.9, doc 22 §9) and before Crawler VM shutdown (2.5/2.9).

### 4.6 Delete

```ts
deleteArtifacts(input: { rawIds?: string[]; derivedIds?: string[]; reason: 'takedown' | 'lifecycle' | 'admin'; signal })
  : Promise<{ rowsDeleted; blobsDeleted; blobsKeptShared }>
deleteArtifactsForSource(sourceId: string, input: { scope: 'derived' | 'all'; reason; signal })
  : Promise<{ rowsDeleted; blobsDeleted; blobsKeptShared; storageKeysDeleted: string[] }>
```

- Deletes rows (derived rows whose `raw_artifact_ids` include a deleted raw row are deleted with it), then deletes each affected blob **immediately** if no remaining row references its key — shared CAS blobs are kept (`blobsKeptShared`). Immediate deletion (not left to GC) is needed to meet the 48 h takedown limit (F-18).
- If versioning is on, also deletes noncurrent versions of deleted keys (OQ-1.3-2).
- Returns deleted `storage_keys` so 6.1 can purge CDN caches.
- Every call writes one structured log record (reason, ids, keys, counts). Caller decides authorization (6.4 admin role, Remove-source orchestrator; OQ-1.3-11).
- **Never used for raw evidence outside these three reasons** (§6).

### 4.7 Maintenance

```ts
runOrphanGc(opts: { dryRun: boolean; signal }): Promise<GcReport>      // daily, doc 22 §9
checkIntegrity(opts: { sampleSize: number; signal }): Promise<IntegrityReport>   // daily, after GC
```

GC algorithm: for each shard `00`…`ff` under each `raw/<type>/` and `der/<kind>/` prefix, list objects; candidates = objects with `LastModified` older than 48 h whose key is in neither registry table (one batched lookup per list page); delete candidates unless a safety stop applies (R16). Shards make the run resumable within its deadline. Integrity check: (a) rows with `stored_at IS NULL` older than 24 h **(proposed)** → alert (stuck or lost spool); (b) a random sample of rows → `HEAD` exists with matching size; (c) a smaller sample fully re-hashed.

Scheduling (cron, BullMQ job names) is 1.4's mechanism; job names follow 1.4's convention.

### 4.9 Events

## 5. Business Rules & Edge Cases

### 5.1 Rules

| # | Rule | Source |
|---|---|---|
| R1 | Raw evidence is never modified. Registry rows are insert-only (except the one-time `stored_at` set); blobs are never overwritten | §6, MB§40 |
| R2 | No file bytes in Postgres; Postgres holds metadata and `storage_key` | §3, D-08 |
| R3 | Every blob key is content-addressed per §3.2 and checked by a DB constraint | §44, F-24 |
| R4 | Blob first, row second; a crash in between leaves only a harmless orphan | DC-02, doc 22 §4 |
| R5 | Raw screenshots are stored at capture resolution (DPR 2 desktop, 3 phone), never resized or upscaled in the raw layer; downscaled images are derived artifacts | DC-20, doc 08 |
| R6 | Screenshots are kept raw + canonical | D-47, GAP§11 |
| R7 | Derived artifacts are never the source of truth and may be deleted and regenerated | §6, §27 |
| R8 | Same `(kind, producer, producer_version, input_hash)` → return the existing artifact; do not recompute or re-upload | §43 |
| R9 | No storage tiering and no lifecycle rules in V0; one bucket | F-33 |
| R10 | Per-blob size limits: `ASSET` ≤ 25 MB (F-10); all other types ≤ `STORAGE_MAX_BLOB_BYTES` (value OQ-1.3-10); checked before upload | F-10, DC-01 |
| R11 | Spooling happens only on the Crawler VM (raw evidence cannot be recreated); App VM producers fail and retry because derived data is regenerable | doc 22 §5, §6 of Blueprint |
| R12 | Registry completeness (§3.5): no other table holds an unregistered `storage_key` | doc 22 §9 (GC needs it) |
| R13 | Re-running a unit attempt never duplicates rows | DC-02 |
| R14 | Orphan GC runs daily and deletes only blobs older than 48 h with no registry reference | doc 22 §9 |
| R15 | Takedown deletes affected derived (and per OQ-1.3-11 raw) artifacts and unshared blobs immediately, within the 48 h limit | F-18 |
| R16 | GC safety stops: GC is paused (flag) after any Postgres restore until an operator re-enables it; GC also refuses to run when R2 holds `raw/` objects much newer than the newest `raw_artifact` row (automatic restore detection, threshold OQ-1.3-13); a run aborts and alerts if candidates exceed a cap (OQ-1.3-13); never touches keys younger than 48 h or outside `raw/`/`der/`. The pause flag is a runtime setting stored where 1.1/1.4 keep admin-editable limits (doc 22 §11) | Derived from R4/R14 and F-35 restore; thresholds OQ-1.3-13 |
| R17 | The bucket is private; only 6.1's delivery path exposes published display derivatives; raw `ASSET`, video, SVG and Lottie blobs are never publicly reachable | F-18, F-42 |
| R18 | Mass reprocessing that reads raw evidence at scale requires a `CostEvent`-based estimate and founder approval (enforced by the reprocessing initiator, not by 1.3) | F-33 |

### 5.2 Failure and edge cases

Doc 22 failure-catalog rows covered: **#16** (storage upload fails / disk fills), **#2/#3/#4** (killed or crashed process mid-upload), **#18** (cost, via storage bytes). DC-16 capture hazards are not storage concerns (owned by 2.3); none apply here.

| # | Case | Detection | Automatic response | Human? |
|---|---|---|---|---|
| E1 | Transient R2 error / timeout | PUT error | Bounded retry inside the 30 s upload deadline | No |
| E2 | R2 outage, or the crawler machine's internet being down (catalog #16) (wave-2 review) | Repeated PUT failures; 2.9 breaker opens | Crawler VM: spool, register rows with `stored_at NULL`, capture continues; flusher uploads on recovery | No |
| E3 | R2 outage on the App VM | `StorageUnavailable` | Job fails; 1.4 retry/DLQ; reconciler/manual retry re-drives | Only if DLQ'd |
| E4 | Spool grows during outage (catalog #16) | `spoolStats`, disk % | Disk guard (2.9): pause intake + flush at 80%; hard stop at 90%; `putBlob` throws `SpoolFull` | Alert at 90% |
| E5 | Process killed between PUT and commit (catalog #2/#4) | No row for the key | Orphan blob; GC after 48 h | No |
| E6 | Process killed between spool write and commit | Spool file, no row | Spool orphan deleted after 48 h by the flusher | No |
| E7 | Zombie worker (lease lost) uploads and tries to commit | 1.4 lease condition rejects the commit | Orphan blob → GC | No |
| E8 | Crawler VM disk lost with unflushed spool | Integrity check: `stored_at NULL` rows older than 24 h with no spool file | Alert (Sentry + daily summary); rows stay; reads fail `BlobNotYetStored` | Yes: re-run affected units (OQ-1.3-17) |
| E9 | On-demand Crawler VM about to stop with a non-empty spool | `spoolStats().files > 0` | Shutdown waits for `flushSpool` (bounded); if still non-empty, do not stop and alert | Yes if flush keeps failing |
| E10 | Same bytes uploaded again (same or other source) | `HEAD` hit | No PUT; new row references the existing blob | No |
| E11 | Same unit attempt registers the same artifact twice | Unique constraint | Return existing row | No |
| E12 | Hash mismatch on read | `IntegrityError` | Reader fails; Sentry alert | Yes: investigate |
| E13 | Row exists, object missing | `BlobMissing` on read or integrity sample | Alert | Yes: re-capture source pages |
| E14 | Asset > 25 MB | `ArtifactTooLarge` before upload | Caller (2.4) records the asset as skipped | No |
| E15 | Code attempts to update a raw row | Trigger raises `ImmutableArtifact` | Transaction aborts; Sentry | Yes: bug |
| E16 | Derived image wider than its raw source (upscale) | `registerDerivedArtifact` check | `InvalidArtifact` | Yes: producer bug |
| E17 | Postgres restored from a backup (up to 24 h old, F-35) | Restore runbook (8.4) sets the GC pause flag; independently, GC's restore detection (R16) sees R2 objects newer than any registry row | GC does nothing until re-enabled, so blobs written after the backup survive for rebuild from raw evidence (GAP§27) | Yes: re-enable |
| E18 | GC would delete an unusual number of blobs (bug, wrong DB) | Candidates > cap (OQ-1.3-13) | Abort the run, delete nothing, alert | Yes |
| E19 | Takedown of a source whose blobs are shared with other sources | Remaining rows reference the key | Delete rows; keep the shared blob; report `blobsKeptShared` | No |
| E20 | Race: a writer `HEAD`s a shared blob that a takedown then deletes, and commits a row | Integrity sample → `BlobMissing` | Alert | Yes (rare) |
| E21 | Versioning on: deleted keys keep noncurrent versions | Delete functions | Also delete noncurrent versions of the keys | No |
| E22 | GC run exceeds its deadline | Deadline (DC-01) | Stop at a shard boundary; next run starts at the next shard | No |
| E23 | Declared MIME type does not match the bytes of a screenshot | Magic-byte check for `SCREENSHOT` (PNG/WebP) | `InvalidArtifact` | No |

### 7.2 Reliability

- Losing Redis loses nothing here (registry is in Postgres, DC-14). Losing R2 temporarily loses nothing (spool, E2). Losing the Crawler VM disk loses only unflushed spool, which is detected (E8).
- Backups: `pg_dump` nightly to `backups/` + R2 versioning, RPO 24 h, RTO 1 day [Decision F-35]; content and restore test owned by 1.7. After a restore, raw evidence plus crawl manifests can rebuild records (GAP§27); GC pause (R16) protects that evidence.
- Every loop and call is bounded (DC-01): upload 30 s, flush per call bounded by `maxFiles` and signal, GC and integrity runs bounded by a deadline (OQ-1.3-13).

### 7.3 Security and privacy

| Deployable / host | R2 access needed | Note |
|---|---|---|
| `worker` on Crawler VM | Read + write on the artifacts bucket | Writes raw evidence; holds the spool |
| `worker` on App VM | Read + write | Reads raw; writes derived |
| `web` (App VM) | Read only, or none (OQ-1.3-20) | Signed URLs for admin; delivery via 6.1 |
| Backups (1.7) | Write to `backups/` | Isolation from crawler credentials: OQ-1.3-1 |

- [Assumption] R2 API tokens scope to buckets, not prefixes; so with one bucket, a compromised Crawler VM token could delete any object, including backups. Raised in OQ-1.3-1.
- Credential values are loaded by 1.1 and stored per 1.7; this Part only names the keys: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `STORAGE_SPOOL_DIR`, `STORAGE_MAX_BLOB_BYTES`, `STORAGE_GC_GRACE_HOURS` (= 48, doc 22 §9) — all **(proposed)** names.
- Encryption at rest: provider default (F-20). No public bucket access (R17).
- V0 collects public marketing pages only, so no unredacted-PII layer is needed now (F-19). **[V2 hook]** authenticated captures need the quarantined raw layer (GAP§3, doc 15); the `raw/` prefix design leaves room for a separate prefix or bucket then.

## 8. Open Questions & Assumptions

### 8.1 Open questions

- **OPEN QUESTION OQ-1.3-1:** F-33 says one bucket. Public delivery of display images (F-18, 6.1) from a private bucket needs one of: (a) a second **public** bucket holding only copies of published display derivatives behind the Cloudflare CDN; (b) a fronting proxy/Worker that serves only allowed prefixes; (c) presigned URLs (these bypass CDN caching). Backups in the same bucket also share credentials with the Crawler VM. — *Why it matters:* making the single bucket public would expose raw `ASSET` blobs (forbidden by F-18) and gated content (F-42); shared credentials put backups at risk. — *Suggested default (suggestion, not a decision):* amend F-33 to "single **evidence** bucket, no tiering", and add (a) a public bucket `designmaxxing-public` written by a `publishDerived`/`unpublishDerived` pair owned by 1.3 and called by the publish step and takedown, plus (b) a separate backups bucket with its own write-only token. Until decided, the evidence bucket stays private.
- **OPEN QUESTION OQ-1.3-2:** F-35 relies on "R2 versioning". [Assumption] R2's S3 compatibility has not offered object versioning in the past; this must be checked against current provider docs. — *Why:* versioning changes delete semantics (GC and takedown must purge noncurrent versions) and is part of the backup plan. — *Suggested default:* if available, enable it with noncurrent-version expiry of 30 days and have delete functions purge versions for takedown; if not available, rely on CAS immutability (keys are never overwritten), deletes only through §4.6, and a retention lock on the backups location.
- **OPEN QUESTION OQ-1.3-3:** DC-02 says "write to content-addressed storage first, then commit the row", but doc 22 also says capture continues and spools locally while storage is down. — *Why:* without a resolution, either capture stops during an R2 outage or rows point at blobs that are not in R2. — *Suggested default:* treat the fsynced spool file under its CAS key as the first durable write; commit rows with `stored_at NULL`; the flusher uploads and sets `stored_at`. No new event: App VM readers get `BlobNotYetStored` and retry via 1.4. Revisit (add a `raw_artifact.stored` event) if DLQ'd jobs from long outages become common.
- **OQ-1.3-4 — resolved in the wave-1 consistency review:** `raw_artifact.capture_attempt_id` → `capture_attempt.id` (1.4's suggestion, finest grain; unit and job are derivable), so no separate `attempt` column. Nullable only for source-level evidence such as robots.txt (needed by 1.5's `robots_artifact_id`). Founder may still change this.
- **OPEN QUESTION OQ-1.3-5:** Mapping onto `raw_artifact_type` for: accessibility tree, computed styles, performance timings, console errors, downloaded third-party media, our own recordings, crawl manifests; and whether per-section images are separate shots (raw `SCREENSHOT`) or crops (derived `section_crop`). — *Why:* type drives the key prefix, size limits and future lifecycle rules (F-33 acts on HTML/DOM/traces and recordings). — *Suggested default:* a11y tree → `UI_TREE`; computed styles → `DOM` (separate document); performance timings → `TRACE`; console errors → `LOG`; downloaded third-party media of any format → `ASSET`; our own recordings (V1 scroll pass) → `VIDEO`; crawl manifests → `LOG` if 2.5 stores them as blobs; section images decided by 2.3 (both supported); (wave-2 review) robots.txt → `ROBOTS_TXT`, sitemap files → `SITEMAP` (P).
- **OPEN QUESTION OQ-1.3-6:** Accept the columns this spec adds beyond §4/F-23: `raw_artifact.attempt, stored_at, meta`; `derived_artifact.sha256, mime_type, size, meta`; and the registry completeness rule (§3.5) as a constraint on other Parts. — *Why:* without `sha256/size` on derived rows, integrity checks and dedupe need extra HEAD calls; without `meta`, DPR and pixel size (DC-20) cannot be checked; without completeness, GC is unsafe. — *Suggested default:* accept all.
- **OPEN QUESTION OQ-1.3-7:** Authoritative `derived_artifact.kind` list and storage (text validated in `packages/schemas` vs a Postgres enum). — *Why:* kinds appear in storage keys and are shared with 3.1, 2.4, 6.1. — *Suggested default:* text + list in `packages/schemas`, starting with the eight kinds in §3.4; producers add kinds additively.
- **OPEN QUESTION OQ-1.3-8:** `raw_artifact_ids` as `uuid[]` (F-23 field name; no FK enforcement) vs a junction table; and whether to record the immediate parent of derived-from-derived artifacts. — *Why:* referential integrity and takedown cascades. — *Suggested default:* `uuid[]` + GIN index + existence check on insert; cascades done in `deleteArtifacts`; no parent column (the `input_hash` already pins the exact input).
- **OPEN QUESTION OQ-1.3-9:** Raw screenshot encoding (lossless PNG vs WebP q90) and compression of text/JSON artifacts. — *Why:* 200–600 GB vs 40–160 GB of raw screenshots (§7.1) and reprocessing quality. — *Suggested default:* PNG for raw screenshots (lossless source of truth; ≈ $9/month at the upper estimate); gzip for HTML/DOM/JSON with `meta.content_encoding = 'gzip'`; SHA-256 always over stored bytes.
- **OPEN QUESTION OQ-1.3-10:** Size cap for non-`ASSET` blobs (`STORAGE_MAX_BLOB_BYTES`). — *Why:* DC-01 requires a bound; a 2880 × 60,000 px PNG can be large. — *Suggested default:* 100 MB; above it the capture Part must tile or fail the attempt.
- **OPEN QUESTION OQ-1.3-11:** On takedown, what happens to **raw** evidence (doc 15: not decided), and which Part orchestrates Remove-source? — *Why:* F-18 requires propagation within 48 h; raw evidence is immutable by principle. — *Suggested default:* delete derived artifacts immediately and raw artifacts too (scope `all`), keeping only blobs shared with other sources; orchestration owned by 1.5 (holder of `takedown_status`) with 6.4 as the UI; confirm with counsel in 8.2.
- **OPEN QUESTION OQ-1.3-12:** When do the F-33 lifecycle rules switch on, and how is the 180-day expiry of raw recordings reflected in the registry, given that a CAS blob may be shared by a newer row? — *Why:* an R2 expiry rule acts on object age and would delete blobs still referenced; the registry would then point at missing blobs. — *Suggested default:* switch on at V1 (when recordings exist); implement the recording expiry as a 1.3 job (`deleteArtifacts` with `reason: 'lifecycle'` on rows older than 180 days, then shared-blob check) rather than an R2 expiry rule; use an R2 transition rule only for the 90-day cold move of `raw/html/`, `raw/dom/`, `raw/trace/`.
- **OPEN QUESTION OQ-1.3-13:** GC and integrity safety numbers: max deletions per run, abort ratio, run deadline, integrity sample sizes. — *Why:* a bug or wrong database can otherwise delete evidence. — *Suggested default:* abort if candidates > 1,000 or > 2% of listed objects; refuse to run if the newest `raw/` object is > 25 h newer than the newest `raw_artifact.created_at`; run deadline 30 min; integrity sample 500 HEADs + 20 full re-hashes per day.
- **OPEN QUESTION OQ-1.3-14:** Storage cost granularity in the `CostEvent` ledger. — *Why:* F-07 cap is measured via `CostEvent`. — *Suggested default:* per-unit `storage_bytes` on the capturing Part's event plus one daily bucket snapshot; decided with 1.6.
- **OPEN QUESTION OQ-1.3-15:** Storage backend for dev and CI (no vendor is decided). — *Why:* tests should not need R2 credentials. — *Suggested default:* a filesystem driver implementing the same interface for unit/CI tests, plus one smoke test against a dev R2 bucket; decided with 1.1.
- **OPEN QUESTION OQ-1.3-16:** Does R2 accept an upload checksum (SHA-256 or Content-MD5) so corruption in transit is rejected server-side? — *Why:* integrity on write. — *Suggested default:* use it if supported; otherwise compare size via HEAD after PUT and rely on read-time verification.
- **OPEN QUESTION OQ-1.3-17:** Lost spool (E8): requeue affected units automatically or leave it to a human? — *Why:* rare, but rows without bytes block downstream work. — *Suggested default:* alert only in V0; operator re-runs the affected units through 1.4's manual retry.
- **OPEN QUESTION OQ-1.3-18:** Which process runs the 60 s spool flusher on the Crawler VM, and how does it interact with the on-demand VM stop (doc 22 §15 #4, not decided)? — *Suggested default:* a loop in the supervisor process (2.9); VM stop is blocked while the spool is non-empty.
- **OPEN QUESTION OQ-1.3-19:** Signed-URL TTL limit. — *Suggested default:* ≤ 3600 s; admin-only use.
- **OPEN QUESTION OQ-1.3-20:** Does the `web` deployable hold R2 read credentials (for admin signed URLs), or does admin viewing go through another path? — *Why:* credential spread on the App VM. — *Suggested default:* `web` gets a read-only token for the evidence bucket; no write.
- **OPEN QUESTION OQ-1.3-21:** S3 client library. — *Suggested default:* the official AWS SDK v3 S3 client, pointed at the R2 endpoint.

### 8.2 Assumptions

- [Assumption] Table names `raw_artifact`, `derived_artifact` follow 1.2's snake_case singular convention (corrected in the wave-1 consistency review); FK targets are named `source` (1.5) and `capture_unit` (1.4). Rename on consistency review if those specs differ.
- [Assumption] Workers on the Crawler VM can write to Postgres on the App VM (implied by F-35 and DC-14).
- [Assumption] R2 provides presigned GET URLs, prefix-scoped lifecycle rules, an infrequent-access storage class for "cold" (F-33), and bucket-scoped (not prefix-scoped) API tokens. Vendor capabilities to verify; prices are point-in-time claims.
- [Assumption] Per-source layout (IF§20) is a logical view over registry rows; keys carry no source id (A-20).
- [Assumption] Section, asset and animation entities reference images through registered artifacts (§3.5), not through their own blob keys.
- [Assumption] The supervisor is a separate process in the same codebase (doc 22 §15 #5), so it can host the spool flusher.
- [Assumption] V0 needs no quarantined unredacted-raw layer because V0 collects only public marketing pages (F-19).
